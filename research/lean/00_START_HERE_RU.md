# QKF: первый Lean-пилот

Это готовый самостоятельный проект для первого этапа формализации QKF.
Нужная версия Lean зафиксирована: **4.33.0**. Для обычной проверки достаточно
Lean и его менеджера сборки Lake. Дополнительные математические пакеты,
Python, Z3, Java и прежний большой архив не требуются.

## Что тебе сделать

1. Установи [Visual Studio Code](https://code.visualstudio.com/).
2. В VS Code открой Extensions / «Расширения», найди **Lean 4** от
   **leanprover**, установи его и пройди Setup Guide. Он установит необходимые
   инструменты для твоей системы. [Официальная инструкция](https://lean-lang.org/install/),
   [нужное расширение](https://marketplace.visualstudio.com/items?itemName=leanprover.lean4).
3. Распакуй архив в обычную папку. В VS Code выбери **File → Open Folder**
   и открой именно `qkf_lean_pilot_2026-09-13`: внутри должны быть
   `lean-toolchain`, `lakefile.toml`, `QKF.lean` и этот файл.
4. Открой **Terminal → New Terminal** и введи:

   ```text
   lake build
   ```

5. Дождись сообщения **Build completed successfully** без ошибок.
   При первой попытке менеджер версий может
   сначала скачать Lean 4.33.0. Сам инструмент занимает сотни мегабайт в
   загрузке и несколько гигабайт после установки; эта загрузка не является
   доказательством и может длиться существенно дольше последующей сборки.

Проект уже создан: выполнять `lake new`, `lake init`, `lake update` или
добавлять Mathlib не нужно. Версию в `lean-toolchain` оставь указанной.

## Вариант с сохранением лога

На Windows после установки можно дважды нажать `CHECK_WINDOWS.cmd`.
Он выполнит сборку, покажет результат и оставит `CHECK_LOG.txt`.

На macOS/Linux можно в терминале открытой папки выполнить:

```bash
bash CHECK_MAC_LINUX.sh
```

Если появится ошибка — пришли `CHECK_LOG.txt` и укажи Windows/macOS/Linux.
Редактировать Lean-доказательства самому не требуется. Если `lake` не найден,
заверши Setup Guide и перезапусти VS Code или терминал: новая установка может
ещё не быть видна старому окну.

Если Setup Guide не открылся: открой любой `.lean`-файл, нажми значок `∀`
справа вверху, затем **Documentation → Show Setup Guide**.

## Как выглядит полезный результат

`lake build` проверяет формальные модули и `Audit.lean`. В последнем зафиксированы
главные теоремы и допустимые зависимости: неожиданная новая аксиома приводит
к ошибке сборки. Фактический вывод аудита сохранён в `validation/axioms.log`.
Главная теорема —
`QKF.mask_successor_all_widths` в `QKF/WordSemantics.lean`.

Она связывает конечное свидетельство QKF с числовым порядком знаковых слов
произвольной длины. Это не только проверка восьми записей таблицы:
в проекте есть общий индукционный переход от всех локальных шагов ко всем
длинам, связь наблюдений с числами и масочная допустимость выходных клеток.

Формализован небольшой используемый фрагмент первой статьи. Полные две статьи,
весь QKF, весь нижний helper и Graal `create` этим пилотом не объявляются
формализованными. Подробности — `docs/SCOPE_RU.md` и `docs/NEXT_STEPS_RU.md`.
Точные результаты выполненной здесь сборки сохраняются в `validation/`.

## Что можно открыть для знакомства

- `QKF/RowRules.lean` — правила вынужденных строк и их корректность.
- `QKF/Gluing.lean` — общая индукция и корректность замкнутого сертификата.
- `QKF/Checked.lean` — проверка конкретных данных QKF и применение общей теоремы.
- `QKF/WordSemantics.lean` — связь с числами, знаком и словами любой длины.
- `QKF/SourceBridge.lean` — согласованность модели ремонтирующей клетки
  с фактором переноса при любом числе шагов.
- `QKF/Examples.lean` — три небольших проверяемых примера.
- `evidence/lower_certificate.json` — точный сертификат предыдущего этапа.

Lean-файлы можно читать и наблюдать за пояснениями в InfoView. Для работы
над следующим этапом достаточно сообщить, успешно ли прошла сборка.
