# Нижняя граница: полученный результат и его пределы

## Что удалось

Получен проверяемый сертификат для переноса через масочные ограничения:
исходный восходящий цикл Graal восстанавливает следующее допустимое слово,
если такое слово существует. Он учитывает обязательные единицы, запрещённые
единицы, необязательные биты, переход через знак и переполнение. Доказательство
охватывает любую положительную математическую разрядность.

На этой основе, с повторным использованием доказанного нисходящего прохода,
проверена вся нижняя процедура при явном условии на контекст. Если маски
совместимы, нижняя граница L типизирована и L≤0 либо маска запрещает
отрицательные слова, возвращённое R удовлетворяет

`L <= R <= x` для каждого допустимого слова `x >= L`.

Поэтому присваивание нижней границы R сохраняет все решения при любой
дополнительной верхней границе. Пустые множества тоже сохраняются: точный
финальный guard исходника гарантирует R≥L даже в пустом случае.

## Почему результат не оказался зеркалом верхней границы

Первая полная проба на ширинах 1..6 проверила 111 972 набора масок, границ
и флагов нуля. На 6 837 непустых входах отдельный helper не вернул точный
минимум. Из них 651 входит в новую доказанную область: здесь ответ безопасен,
но слабее точного минимума. Вне этой области встречается и потеря решений.

Пример на реальной 8-битной ширине: must=0, may=192, L=1, ноль разрешён.
Допустимое после ограничения слово — 64, но отдельный `computeLowerBound`
возвращает 127. Полный `create(8,1,127,0,192,true)` на том же исходнике
правильно возвращает константу 64: он сначала уточняет маски.
Это контрпример к слишком широкому контракту helper, а не обнаруженная
ошибка Graal `create`.

Другой пример: must=1, may=129, L=−1, U=127. Отдельный helper возвращает 0,
а минимальное допустимое слово — 1. Здесь ноль служит безопасной границей,
хотя сам не принадлежит маске. Полный `create` возвращает константу 1.
Требовать принадлежность возвращённой границы маске на каждом промежуточном
шаге было бы неверно.

В пустом случае нет и единого числового MAX-маркера. Например, на ширине 1
для must=may=0 и запрета нуля helper возвращает 1, за пределами 1-битного
знакового диапазона. Причина — нативные `ctz(0)=64` и маскирование расстояния
сдвига Java. Числовой результат сохранён; пустота определяется отдельным
проверенным контрактом верхней границы.

## Что именно сделано через теорию проекта

У исходного восходящего цикла три возможных состояния управления/переноса:
ещё не начато, начато без переноса, начато с переносом. Первое и третье
имеют одинаковое наблюдаемое действие на будущие масочные клетки. Проверен
фактор из двух классов и сохранение выдаваемого бита и продолжения.

На защищённом носителе P({0,1}) построены восемь строк. Для каждой два
нативных атомарных значения вынуждают ещё два через объединение и пересечение.
Полные таблицы и их ядра проверяются; именно эти таблицы участвуют в склейке.

Совместное наблюдение переноса и сравнений замкнулось на восьми состояниях:
48 переходов и 32 знаковых завершения. Старый проход даёт ещё 49 состояний.
Внешняя процедура проверена по 47 293 полным предпорядкам семи величин и
четырём сочетаниям двух флагов. Нативные факты и доказанные леммы оставляют
25 737 допустимых порядковых случаев; все удовлетворяют контракту.

Форма наблюдений и условия композиции выбраны исследовательски. Вычисление
строк, построение замкнутого носителя и проверка сертификата автоматизированы.
Общий автоматический вывод любого Java-алгоритма из теории не получен.
Разбор всего lower-helper остаётся ограниченным мостом, распознающим его
структуру; переименование переменных и несколько семантических вариантов
не мешают доказательству.

Для широких слов независимый oracle перечисляет не более девяти свободных

Из допущенных проверок API классифицировал 76 230 как точный минимум,
813 как безопасную неточную границу и 33 207 как пустой носитель. В группах
есть пересекающиеся входы; это количества проверок, а не независимых задач.
Для полной малой группы соответствующие числа: 62 637, 651 и 12 816.

Отвергнуты 20 испорченных сертификатов и подмена результата специализации.
Пять изменённых Java-алгоритмов не прошли доказательство; для каждого
сохранён реальный нативный контрпример. Это 11 160 вызовов мутантов,
отдельно от проверок исходника. Три эквивалентных варианта получили новые
полные сертификаты: переименование, обращение порядка операндов сравнения,
сложение вместо OR в клетке, где проверяемый бит заведомо равен нулю.

Сохранено и ограничение выбранной композиции: строгий предшественник `<`
с последующим successor не удовлетворяет повторно используемой лемме о
максимуме `<=`. Наш producer его отвергает, хотя 2 232 нативные проверки
полной изменённой процедуры не показали нарушения сохранения. Отказ в
промежуточной лемме сам по себе не доказывает ошибочность всего алгоритма.

## API и границы результата

`CheckedLowerContract.refine` проверяет исходный контракт, возвращает явный
отказ для положительной L с всё ещё разрешённым отрицательным знаком,
сохраняет точное исходное R и отдельно сообщает пустоту/точность.
В пустом случае `refined_spec` отражает исходное присваивание и может содержать
внетиповую нижнюю границу; потребитель обязан завершить обработку по
`joint_empty`, а не передавать такую запись как новый непустой вход.

Пустота опирается на предыдущую универсальную теорему верхней границы.
Если носитель непуст и R принадлежит ему, из R≤x автоматически следует
точность минимума; иначе заявляется только безопасная граница.

Нативная семантика Java относится к ширинам до 64; производственные ширины
этого проекта — 1,8,16,32,64. Остальные малые ширины — диагностика helper.
Ширины больше 64 относятся к явно описанному математическому продолжению;
исполняемый API ограничен 4096 по ресурсам, не по теореме.

Полный `create`, допустимость всех его временных состояний, уточнение масок
и стабилизация за три итерации ещё не доказаны. Покрытие целых программ
остаётся Graal 2/5 (AND, OR), control 1/5; исторический NiceToMeetYou 11/39,
104/411 компонентов. Нового внешнего корпуса или сравнения с SMT не было.

Это содержательное развитие механизма совместных наблюдений: он теперь
работает и для восходящего восстановления слова с переносом. Следующая
цель — композиция с реальным вызывающим кодом, чтобы условия helper
выводились из общего носителя на каждом шаге.
