# Что уже сделано

Подготовлен и собран самостоятельный проект **Lean 4.33.0**. Все доказательства
пилота прошли проверку Lean. Тебе не нужно их дописывать: инструкция в
`00_START_HERE_RU.md` нужна для повторения проверки на своём компьютере.

## Содержательный результат

Наш конечный сертификат переноса теперь связан с формальным доказательством
для слов **произвольной длины**. В доказательстве участвуют вынужденные строки,
фактор фаз переноса, общая склейка локальных шагов и числовой смысл наблюдений.
Восемь состояний сертификата проверены вместе с 48 переходами и 32 допустимыми
знаковыми завершениями. Отдельно доказана полнота шести типов колонок.

Главный результат: если существует допустимое по маске слово x больше g,
вычисленное t сохраняет маску и удовлетворяет **g < t ≤ x**. Это теорема
об явно заданной математической модели successor. Связь модели исходной
ремонтирующей клетки с фактором доказана для любого числа незнаковых шагов.

Это первый формализованный фрагмент QKF. Полные две статьи, вся нижняя
процедура Java и `create` ещё требуют отдельного переноса. Экспериментальное
покрытие и оценки быстродействия этот этап не изменяет.

## Что реально проверено при подготовке

- Чистая сборка через `lake build`, включая обязательный модуль `Audit`:
  **успешно**, без предупреждений. На этой машине после установки Lean
  запуск проверочного сценария занял около 7 секунд; это не оценка
  производительности QKF и не обещание времени установки на другой машине.
- После распаковки ZIP в новую папку без кеша повторная сборка:
  **успешно**, исходники совпали по SHA-256.
- Повторный вывод списков аксиом: **успешно**. В главном доказательстве только
  стандартные `propext` и `Quot.sound`; в правилах вынужденных строк и
  единственности продолжения с атомов аксиом нет.
- Экспорт таблиц сверён с точным сертификатом предыдущего этапа; хеши всех
  приложенных исходных свидетельств совпали.
- Три числовых примера, включая переход от −1 к 0 и одноразрядный случай,
  проверены Lean.
- Четыре намеренных повреждения в отдельных копиях проекта отклонены:
  неверное начальное состояние, неверный переход, испорченная клетка строки
  и подмена доказательства заглушкой. Последний случай отклонил аудит аксиом.

Логи и машиночитаемые результаты находятся в `validation/`. Проверка
выполнялась на Linux x86_64. Сценарий Windows приложен, его выполнение
на Windows здесь не проверялось.

## Для самостоятельной дополнительной проверки

Обычного `lake build` достаточно. При желании вывести аксиомы отдельно:

```text
lake env lean validation/Axioms.lean
```

Разработчику с установленным Python 3 доступны также:

```text
python scripts/export_certificate.py --check
python scripts/negative_checks.py
```

Второй сценарий намеренно запускает четыре испорченные копии и ожидает
ошибки в них. Он не меняет исходный проект. Эти дополнительные действия
не нужны для первого пользовательского запуска.

Техническая особенность локальной проверки описана в `validation/RESULTS.json`:
в изолированной среде отсутствует procfs, поэтому использован адаптер
определения пути к самому исполняемому файлу. Официальный Lean не изменялся,
SHA-256 его архива проверен. Адаптер не меняет проверку доказательств;
на обычной пользовательской установке он не используется.
