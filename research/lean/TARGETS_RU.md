# Прогон 4: Lean-проверка целевых наблюдений

15 сентября 2026 года. Самостоятельный формальный слой поверх неизменённого
Lean-пилота. Первая полностью успешная проверенная ревизия исходников и
отрицательных контролей: `4315e8f61afff66fcf1eac993644d8c1a021cea3`.
Этот документ добавлен отдельным следующим коммитом.

## Результат

Lean 4.33.0 проверяет общий конечный сертификат, связывает наблюдения с
числовыми словами и выводит точный циклический преемник для любой положительной
длины допустимого входного слова. Два примера используют данные нового
типизированного пути: исходный фактор и фактор варианта с лишним регистром.

Для каждого примера экспортированы 2 класса исходного фактора, 7 вопросов цели,
9 совместных состояний и 54 перехода по полному алфавиту из 6 колонок. Эти числа
не объявляются минимальными. Отличие от прежних 8 состояний / 48 переходов
связано с явным разделением пустой инициализации и положительной длины в новой
схеме, а не с новым покрытием программ.

## Точная область теоремы

Вход — произвольный непустой список допустимых колонок `(must, may, seed)`;
его длина есть ширина. Числовое значение задаётся обычной двоичной суммой
младших разрядов. Независимое множество `Masked` состоит из значений списков
той же длины, содержащих обязательные биты и не выходящих за разрешённую маску.
Оно определяется без исходного алгоритма и без сертификата.

Результат принадлежит этому множеству. Если существует допустимое число,
строго большее начального, результат — наименьшее из таких чисел. Иначе
результат равен значению `must`, то есть минимуму маски. Одноэлементная маска
обрабатывается тем же утверждением. Конкурент не является входом исходной
машины: отдельно доказано, что его выбор не меняет результат программы.

## Модули

| Модуль `QKF/Targets/` | Содержание |
|---|---|
| `Numeric.lean` | Двоичное значение, границы нижних частей, равенство и порядок при добавлении старшего бита |
| `Rules.lean` | Типизированные выражения и формулы; точность перехода каждого вопроса относительно числового смысла |
| `Kernel.lean` | Полный алфавит, конечные машины, проверка сертификата и общая индукция по любой положительной длине |
| `Successor.lean` | Независимая защищённая цель преемника и её числовой смысл |
| `Words.lean` | Полнота конкурентов, независимость выхода, экстремумы маски и точное свойство циклического минимума |
| `Data.lean` | Только экспортированные таблицы двух проверенных пакетов |
| `Checked.lean` | Проверка таблиц через `decide`, совпадение с внешней целью, два all-width результата и одноэлементный случай |
| `Audit.lean` | Обязательный аудит точных зависимостей от аксиом |

Новый путь переиспользует только общую индукцию `QKF.Gluing`, а не прежние
ручные фазы, carry-таблицы или теорему старого `SourceBridge`.

Основные имена:

```text
QKF.Targets.atom_snoc
QKF.Targets.accepted_all_widths
QKF.Targets.output_independent
QKF.Targets.masked_extrema
QKF.Targets.cyclic_successor_all_widths
QKF.Targets.original_cyclic_successor
QKF.Targets.irrelevant_cyclic_successor
QKF.Targets.original_singleton
```

`accepted_all_widths` относится к любому заданному в Lean конечному автомату
восходящего входного профиля и допустимой программе вопросов, чей сертификат
принят. Это не теорема обо всех программах Java и не формализация
нисходящего адаптера. Числовая семантика битовых выражений определяется
координатным вычислением и двоичным значением; отдельная связь с `Nat.land`
или внешней реализацией `BitVec` здесь не заявляется.

## Независимая цель и доверенная граница

Экспортированная программа вопросов обязана совпасть с `successorProgram`,
заданной независимо в `Successor.lean`. Положительный сертификат более слабой
цели не превращается в теорему преемника. Начало, все рёбра, типы вопросов,
полнота колонок и защищаемая цель являются отдельными обязательствами.

Lean проверяет математические определения, доказательства и данные конечных
факторов. Он не проверяет Java-парсер, арифметические правила извлечения
исходного фактора, Python-проверяющие, JSON-компилятор или экспортёр в Lean.
Идентичность экспорта подтверждается воспроизводящими проверками и
`Data.export.json`, но хеш не является доказательством правильности перевода.

Полная локальная поставка прогона 4 включает базу прогона 3, два исходных
пакета в `evidence/typed_targets/`, экспортёр `export_lean_targets.py` и его
10 тестов. Они воспроизводят `Data.lean` и `Data.export.json` побайтно после
обычной проверки исходного пакета. На удалённой ветке этого PR находится
самостоятельный Lean-слой поверх `main` после PR №5; неопубликованный Python-код
прогонов 2–3 этой веткой не подменяется и не считается опубликованным.

## Аксиомы

Аудит через `#guard_msgs` закрепляет точные списки, а не только печатает их.

| Теоремы | Зависимости |
|---|---|
| `atom_snoc`, `accepted_all_widths` | `propext`, `Quot.sound` |
| `original_accepted` | `propext` |
| `cyclic_successor_all_widths`, обе конкретные теоремы, `original_singleton` | `propext`, `Classical.choice`, `Quot.sound` |

Это стандартные аксиомы Lean, не утверждение об отсутствии аксиом. Новых
пользовательских аксиом и доказательственных пропусков нет. `native_decide`
и `bv_decide` не используются. Отрицательные контроли требуют сначала
доказать ложность повреждённого условия, чтобы синтаксическая ошибка не могла
считаться успешным отвержением сертификата.

## Воспроизведение

Требуется закреплённая версия Lean из `lean-toolchain`. Из корня репозитория:

```sh
cd research/lean
lake build
lake build QKF.Targets.Audit
cd ../..
python research/lean/scripts/check_target_mutations.py --output reproduction/lean_target_controls_01
```

Первый `lake build` проверяет прежний пилот; новый слой вызывается второй
командой явно. Именно её требует новый workflow `Lean target kernel`.
Последний каталог должен быть новым.

Только в полной локальной поставке прогонов 2–4:

```sh
python -O -m research.observations.export_lean_targets --check
python -m unittest discover -s research/observations/tests -v
python -O -m unittest discover -s research/observations/tests -v
```

На полной локальной базе прошли 217 тестов (207 прежних + 10 экспортных),
отдельно обычный режим и `-O`. Проверены прежние 23 типизированных пакета,
18 пакетов v1 и 16 сертификатов композиции; нерешённый отчёт композиции
остаётся нерешённым. Локальный Python — 3.13.5. Сам Lean запускался не локально,
а в GitHub Actions на опубликованном формальном слое.

## Проверенная сборка

[Lean target kernel, run 34958829795](https://github.com/Len989/QKF-Certifier/actions/runs/34958829795)
завершился успешно для `4315e8f`: прежний Lean-пилот, новые числовые теоремы,
аудит и все 10 отрицательных контролей. Сборка использовала Lean 4.33.0,
commit `d8b18978322de05a8f3dba51ef03cf5461676c17`. Артефакт
`10392611261` сохраняет версию, точную ревизию, хеши всех восьми Lean-модулей,
журнал сборки и оба результата каждого отрицательного контроля.

Набор повреждений: исходное начало, начало сертификата, ребро, ответ
масочного вопроса, выходная ячейка, стирание положительной ширины, ошибка типа
вопроса, подмена сильной цели слабой, неполный независимый алфавит и неправильный
приоритет разрядов в сравнении. В каждом случае Lean доказывает `gate = false`,
после чего отвергает отдельное утверждение `gate = true`.

Промежуточные неуспешные сборки при разработке не считаются принятием. Успешный
результат относится к указанной ревизии; документационные коммиты получают
собственный повтор CI.

Полный Java-метод, знаковая семантика JVM, Python-реализация компилятора целей,
нисходящий профиль и композиция прогона 3 не становятся Lean-доказанными от
соседства с этим модулем. Новое покрытие KnownBits или внешний эксперимент
здесь не заявляются.
