# Вывод исходных наблюдений и общих срезов из Java

Дата: 14 сентября 2026. Продолжение исследовательской ветки после этапа
минимального фактора. Это дополнение к прототипу, а не новый релиз CLI.

## Что изменилось

Раньше адаптер нисходящей ячейки заранее задавал словарь сравнений
«меньше / равно / больше» и объяснял, какие части слова используются совместно.
Дальнейший вывод остаточных наблюдений и минимального фактора уже был
автоматическим, но эта начальная информация оставалась ручной.

Теперь новый путь начинается с тела настоящего Java-метода `setOptionalBits`.
Он извлекает вопросы из условия ветвления, различает входные слова и связывает
части выражений по месту единственной записи. Затем строятся достаточное
наблюдение над целыми числами, действия суффиксов, локальные строки,
остаточное наблюдение и минимальный фактор конечного потребителя.

Для исходного метода система снова получает 15 остаточных состояний и 10
классов. В этом пути готовые три состояния сравнения и их таблицы не подаются
на вход. Изменение условия на `bound + 1` или `bound + 3` изменяет сам словарь
наблюдений, а не только итоговую таблицу.

## Как выводятся вопросы

Пусть `d` — разность двух уже прочитанных двоичных слов. Дописывание битов
`a` и `b` действует по правилу

\[
T_\delta(d)=2d+\delta,\qquad \delta=a-b.
\]

Условие исходника `trial <= bound + k` даёт защищаемый вопрос `d <= k`.
Его обратный образ при дописывании битов имеет точную форму

\[
T_\delta^{-1}(d\le t)\;=\;
\left(d\le\left\lfloor\frac{t-\delta}{2}\right\rfloor\right).
\]

Производитель замыкает пороги по этому правилу. Проверяющий проверяет
происхождение каждого порога, замкнутость всей семьи, разбиение множества
целых на интервалы и постоянство ответов потребителю внутри каждого интервала.
Переход проверяется для всего интервала, включая неограниченные концы;
проверки одного представителя недостаточно.

Для смещений 0, +1 и +3 получаются соответственно пороги `[-1, 0]`,
`[-1, 0, 1]` и `[-1, 0, 1, 2, 3]`: три, четыре и шесть значений наблюдения.
Эта арифметическая проверка не зависит от выбранной длины слова. Однако
перенос её результата на семантику всей Java-программы требует отдельного
обоснования; текущий фронтенд имеет явно ограниченный контракт.

Для нижней части слова выводится конечная семья преобразований этих
интервалов. Пустой суффикс задаёт тождественное преобразование. Добавление
очередного младшего участка задаётся композицией с действием его бита.
Сертификат содержит происхождение преобразований и полную проверяемую
таблицу замыкания. Готового словаря суффиксных сравнений здесь нет.

## Как обнаруживаются общие части

Из нисходящего обхода и единственной операции `value |= bit` следует:
старшая часть пробного слова совпадает с уже обработанным результатом;
младшая часть ещё совпадает с исходным `initialValue`; запись затрагивает
только текущий бит. Сторона сравнения определяется по идентичности входного
аргумента. Эти связи сохраняются в извлечённом представлении исходника.

Проверяющий заново извлекает представление и связывает с ним сертификат.
Подмена общей старшей части на независимую переменную, разрыв связи младших
частей и подмена вызываемого `CodeUtil.mask` отклоняются.

Показательная модификация — сравнение с `initialValue`. Анализатор видит,
что обе нижние части принадлежат одному входному слову. Поэтому допустимые
битовые колонки удовлетворяют равенству соответствующих битов, а все нижние
действия сводятся к тождественному. Это извлечённая зависимость по коду.

Здесь всё ещё доверены общий закон разбиения слова, правила арифметики и
распознавание поддержанного цикла. Это не универсальный анализатор потока
данных: произвольную структуру программы он пока не восстанавливает.

## Связь с теорией QKF

Потребитель задаёт защищаемые ответы. Обратные образы определяют достаточное
наблюдение; совместные участки сохраняются в локальных отношениях. По
атомарным значениям строк восстанавливаются вынужденные значения и ядра.
После построения остаточного наблюдения выводится его фактор относительно
защищаемого конечного ответа. Для различных классов сохраняются разделяющие
контексты, поэтому минимальность последнего фактора проверяется.

Этот шаг реализует эту последовательность из первых двух статей. Обратные
образы, интервальные разбиения и замыкание преобразований сами по себе —
известные математические конструкции; новой общей теории их открытия здесь
не заявляется. Практический результат — сокращение ручного входа и связанная
цепочка проверок от конкретного кода до вынужденных строк и фактора.

Начальная пороговая семья достаточна, но её минимальность для всех сочетаний
предикатов не утверждается. Например, разложение равенства на два порога
может сохранять лишнее различие. Минимальность утверждается для последующего
конечного фактора и его указанного потребителя.

## Результаты воспроизводимого эксперимента

| Условие сравнения | Значений контекста | Действий суффикса | Остаточных состояний | Классов фактора |
|---|---:|---:|---:|---:|
| `trial <= bound` | 3 | 3 | 15 | 10 |
| `trial <= bound + 1` | 4 | 6 | 27 | 13 |
| `trial <= bound + 3` | 6 | 13 | 62 | 20 |
| `trial <= initialValue` | 3 | 1 | 4 | 2 |

Для каждого из первых трёх вариантов проверены все 37 448 слов над
допустимыми колонками ширины 1–5. Для последнего, с меньшим алфавитом, —
1 364 слова. Всего 113 708 проверок: принятие слова фактором совпало с
равенством предложенного результата и результата целочисленного исполнения.

Для каждой конкретной комбинации входов из этого опыта выполнен также
настоящий Java-метод с неизменённым извлечённым телом и исходным `mask`.
Получилось 9 330 входов на каждый из первых трёх вариантов и 363 на последний,
всего 28 353 вызова метода. Расхождений с целочисленным исполнением нет.
Это представители допустимых колонок, а не полный перебор четырёх входных
параметров Java. Полезное слово ширины `w` помещается в вызов с `bits=w+1`
и фиксированным нулевым знаковым битом.

Прошли 47 тестовых методов, из них 10 новых. Новые проверки включают
30 сочетаний оператора сравнения и смещения, большие целые до `10^80`,
12 переименований исходника, три эквивалентные записи условия, 21 подмену
составного сертификата и 11 неподдерживаемых изменений кода. Отдельно
проверены различие Java-литералов `1` и `1L`, изменение реализации `mask`,
неподдержанные восьмеричные литералы и исчерпание бюджетов.

Полная проверка сертификата работает в свежем процессе, в том числе с
`python -O`, при заблокированных производителях, старых адаптерах, SMT и
запуске внешних процессов. Java нужен только для независимого испытания
исполнения, а не для повторной проверки доказательного пакета.

## Границы результата

Поддерживается один нисходящий цикл с однобитовой OR-записью, один неизменяемый
вход на правой стороне сравнения, шесть операторов сравнения, целые смещения
и булевы комбинации поддержанных вопросов. При неподдержанной структуре
исходника выдаётся отказ. Математический профиль использует беззнаковые
слова с дополнительным нулевым знаком и непересекающиеся начальную и
необязательную маски. Переполнение `long`, произвольные знаковые входы и
нестандартные сдвиги в этот контракт не входят.

Бюджеты: не более восьми интервальных значений, шестнадцати суффиксных
действий и шестидесяти четырёх остаточных состояний в составной цепочке.
Исчерпание бюджета не создаёт сертификат. Контекстные строки теперь могут
использовать атомарное заполнение, как и строки фактора; это избегает
перечисления всех подмножеств. Старое полное представление сохранено и
сопоставлено с компактным на исходном условии и смещениях +1/+3.

Это существенный шаг в автоматизации начала цепочки: словарь наблюдений
теперь может меняться вслед за арифметикой исходного условия. До вывода
наблюдений для произвольного кода ещё далеко. Покрытие KnownBits остаётся
11/39 полных программ и 104/411 компонентов. Новых теорем Lean и общей
теоремы о Java-методе на всех машинных словах этот этап не добавляет.

Следующая разумная проверка обобщения — выразить вторую форму ячейки через
те же правила операций и срезов. Это покажет, какие части нынешнего
фронтенда действительно переиспользуются, прежде чем расширять корпус.

## Файлы и запуск

Исходник: `research/graal/native/IntegerStamp.java`.
SHA-256: `1a827adb88f57b8f612979af5b90016077cbf4dad4c54b34e539fee5fce01c95`.
Он сохранён без изменения; экспериментальные варианты лежат отдельно.

```sh
python -m unittest discover -s research/observations/tests -v
python -m research.observations.run_source_experiment reproduction/source_experiment --native
python -O -m research.observations.source_cli check-java reproduction/source_experiment/original.certificate.json
```

Каталог вывода должен быть новым. Последняя команда заново читает
зафиксированный исходник репозитория. Для изменённого файла:

```sh
python -m research.observations.source_cli derive changed.java certificate.json
python -m research.observations.source_cli check changed.java certificate.json
```

`evidence/source/` содержит четыре источника, извлечённые представления,
модели, сертификаты, объяснения факторов, результаты, журналы и манифест
хешей. `java_words.py` отвечает за контракт исходника, `word_producer.py`
за вывод вопросов, `word_kernel.py` за их проверку, `source_factor.py`
за всю составную цепочку. Эксперимент включён в GitHub Actions.
