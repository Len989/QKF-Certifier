## Результат

Оба существующих профиля теперь проходят один пользовательский маршрут:

```text
исходник + явно выбранный профиль + независимая спецификация
  → вывод исходной модели
  → проверка сертификата модели
  → поиск доказательства свойства или контрпримера
  → независимая проверка
  → общий пакет и результат
```

Новый вход — `python -m research.observations.run`. Он предоставляет команды
`spec`, `verify`, `check`, `explain`. Поиск запускает только `verify`.
`check` и `explain` заново проверяют оба доказательства; исходник и спецификация
обязательны как внешние аргументы. Для повторной проверки не нужны производители,
SMT, Java или исходное окружение генерации пакета.

| Профиль | Независимые требования | Существующие проверяющие |
|---|---|---|
| `descending` | `maximum`, `bound` | `source_factor`, `property_kernel` |
| `ascending` | `cyclic_successor`, `membership` | `ascending_kernel`, `successor_kernel` |

Старые команды, схемы и математические проверяющие не изменены. Устанавливаемый
публичный `qkf` не расширен. Это объединение исследовательского интерфейса,
а не новый алгоритм вывода наблюдений или новая теорема о Java.

## Пакет и граница доверия

Схема `qkf-research-package-v1` имеет семь полей:

```text
schema, profile, contracts, binding, dependencies, proofs, result
```

`proofs.source` и `proofs.property` содержат прежние сертификаты в их исходных
схемах. Они включены в пакет, а не загружаются по указанным пакетом путям.
Граф зависимостей фиксирован: исходное доказательство зависит от внешнего
исходника, доказательство свойства — также от исходного доказательства и
внешней спецификации. Это ещё не общий граф композиции программных регионов.

Связывание включает SHA-256 точных UTF-8 байтов исходника и канонические JSON-хеши
внешней цели и обоих сертификатов. Комментарии и переводы строк исходника
значимы; форматирование JSON незначимо. Хеши устанавливают идентичность данных,
но не авторство и не правильность доказательства.

При повторной проверке профиль выбирается из внешней спецификации. Дополнительно
переданный `--profile` обязан ей соответствовать. Пакет не может назначить
другой проверяющий, выбрать более слабую цель или добавить предпосылки.
Проверяются сами вложенные доказательства, после чего результат вычисляется
заново. Сохранённое поле `result` должно точно совпасть с этим результатом.

Отдельные тесты заменяют привязку слабой цели на сильную с пересчётом хешей.
Такие пакеты отвергаются на защищаемом обязательстве прежнего проверяющего:
для строгого нисходящего условия граница не становится максимальностью,
а для восходящего OR принадлежность маске не становится преемником.

`explain` не пересказывает недоверенный сохранённый текст: он выполняет тот же
повтор проверки и выдаёт цепочку утверждений, предпосылки, обязательства,
границы результата, размер замыкания либо проверенный числовой контрпример.

Новый доверенный слой — проверка оболочки и JSON, выбор профиля и сборка общего
результата. Ограниченные фронтенды, правила срезов и семантика целей по-прежнему
доверенные. Доказательство модели и доказательство свойства остаются разными
утверждениями; успешность первого не заменяет второе.

## Исходы, бюджеты и файлы

| Статус | Код | Смысл |
|---|---:|---|
| `certified` | 0 | Независимое свойство проверено в указанном контракте |
| `refuted` | 1 | Проверен конкретный контрпример |
| `budget_exhausted` | 2 | Исчерпан бюджет, пакета доказательства нет |
| `invalid_certificate` | 3 | Повреждённый пакет, привязка, доказательство или сохранённый результат |
| `unsupported` | 4 | Исходник вне поддержанного профиля |
| `input_error` | 64 | Ошибка аргументов, цели, бюджета, доступа или конфликт вывода |
| `internal_error` | 70 | Неожиданный сбой либо отклонение сгенерированного доказательства |
| `written` | 0 | Только запись шаблона командой `spec`, не доказательство |

`verify` принимает отдельный JSON бюджет с разделами `source` и `property`.
Поддержанные ключи и диапазоны перечислены в [руководстве](UNIFIED_RUN.md).
Неизвестные ключи, логические значения вместо целых и выход за диапазон
отвергаются. Это бюджеты размера поиска, а не новый лимит времени или памяти
процесса. При повторной проверке бюджет не ослабляет обязательства.

Полный положительный либо отрицательный результат записывает `package.json`
и `result.json` в новый каталог. Неподдержанный источник и исчерпание бюджета
оставляют только `result.json`, без пакета. Существующие файлы, каталоги и
символьные ссылки не заменяются. После ошибки записи может остаться частичный
каталог; повреждённый частичный пакет не проходит проверку.

Чтение ограничено 2 MiB для исходника, 64 KiB для цели или бюджета, 32 MiB для
пакета. Дублирующиеся JSON-ключи и нечисловые константы NaN/Infinity запрещены.
Транспортные ограничения не ограничивают ширину, квантифицированную в теореме.

## Проверенная контрольная популяция

Через общий интерфейс выполнены все прежние целевые случаи:

| Популяция | Случаев свойства | Сертифицировано | Опровергнуто |
|---|---:|---:|---:|
| Четыре нисходящих варианта, две цели | 8 | 4 | 4 |
| Пять восходящих вариантов, две цели | 10 | 7 | 3 |
| Всего | 18 | 11 | 7 |

Это 18 сочетаний источника и требования из прежних экспериментов, не 18 новых
программ. Семь опровержений — ожидаемые отрицательные контроли, а не сбой
проверки. Исходный максимум сохраняет 49 совместных состояний и 980 переходов,
исходный преемник — 8 состояний и 48 переходов.

Свежий вывод исходных и целевых сертификатов сопоставлен с их прежними
сохранёнными версиями. Затем те же оболочки восстановлены без поиска.
Совпали вердикты, результаты проверки, размеры и канонические хеши всех пакетов.
Их размеры в этой версии — от 7 009 до 40 888 байт; это размеры оболочек с
обоими доказательствами, без внешнего исходника и файла цели.

## Тесты и происхождение результатов

На ревизии `53f2aa9` прошли **131 метод тестирования наблюдений**:
98 прежних и 33 новых. Новые тесты покрывают общий пакет, все четыре цели,
CLI, отрицательные результаты, бюджетные отказы, подмену цели и источника,
повреждения вложенных доказательств после пересчёта хешей, перенос пакета,
защиту файлов и классификацию внутренних ошибок.

В свежих процессах обычного Python и `-O` проверены `check` и `explain` для
всех 18 случаев и повреждённого пакета. Импорты производителей, старых Graal-
адаптеров, SMT, нативных обвязок и `subprocess` заблокированы. Отдельно в таких
же условиях проверено восстановление всех пакетов из сохранённых доказательств.

На этой же ревизии успешны три workflow:

- [Unified research run](https://github.com/Len989/QKF-Certifier/actions/runs/34936137745):
  Python 3.10 и 3.12, новые тесты, свежий вывод 18 пакетов, восстановление без
  поиска под `-O`, совпадение пакетов, общий `check` и `explain`.
- [Research and Lean](https://github.com/Len989/QKF-Certifier/actions/runs/34936137540):
  все 131 тест, прежние исследовательские и нативные эксперименты,
  воспроизведение KnownBits/Graal и существующая сборка Lean.
- [Test and build](https://github.com/Len989/QKF-Certifier/actions/runs/34936137669):
  прежние проверки устанавливаемого пакета и сборки.

Проверки выполнены в GitHub Actions. Локальный вычислительный сеанс не имел
прямого сетевого доступа для клонирования репозитория; локальный прогон здесь
не заявляется. Повторённые нативные испытания прежнего workflow не прибавлены
к покрытию и не объявляются новой популяцией входов.

`evidence/run/BASELINE.json` сохраняет точные отпечатки 18 пакетов из первого
успешного общего эксперимента на `c6a69fd`, run `34935915604`. Последующий тест
`test_run_baseline.py` сначала полностью воспроизводит доказательства и только
затем сверяет отпечатки. Хеш никогда не заменяет принятие проверяющим.

Полные результаты сохраняются артефактами общего CI на 30 дней. После их
истечения пакеты восстанавливаются без производителей из неизменённых
`evidence/property`, `evidence/ascending` и `evidence/successor`, хранящихся в Git.

## Воспроизведение

Из корня полной копии этой ветки, Python 3.10+, новые пути вывода:

```sh
python -m research.observations.run spec successor.goal.json --profile ascending --claim cyclic_successor
python -m research.observations.run verify research/graal/native/IntegerStamp.java --profile ascending --spec successor.goal.json --output reproduction/common_successor_01
python -O -m research.observations.run check research/graal/native/IntegerStamp.java --spec successor.goal.json --package reproduction/common_successor_01/package.json
python -O -m research.observations.run explain research/graal/native/IntegerStamp.java --spec successor.goal.json --package reproduction/common_successor_01/package.json

python -m research.observations.run_unified_experiment reproduction/common_fresh_01
python -O -m research.observations.run_unified_experiment reproduction/common_retained_01 --retained-only
python -m unittest discover -s research/observations/tests -v
```

## Граница завершённого этапа

Общий пользовательский маршрут, версия пакета, независимая повторная проверка,
раздельные исходы, сохранение прежних результатов, тесты и воспроизводимость
реализованы. Критерии прогона 1 выполнены на указанной проверенной ревизии.
Изменения предлагаются отдельным PR; автоматически в `main` они не объединяются.

Не добавлены общий язык требований, композиция регионов, новые правила операций,
полная знаковая семантика JVM, доказательство `computeLowerBound`/`create`, новая
теорема Lean или покрытие KnownBits. Эти границы сохранены в самом результате.
Следующий отдельный прогон — сборка целевых наблюдений из общих правил;
работа над ним этим отчётом не объявляется выполненной.
