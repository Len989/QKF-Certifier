# Наблюдения восходящего прохода из операций Java

14 сентября 2026. Вторая структура исходных операций в плане v0.3.

## Что получилось

Теперь начальную модель восходящего прохода строит новый разбор операций
самого Java-блока. Старые `source_cell`, `PHASES`, `quotient` и заранее
выбранный носитель переноса не используются. Из тела программы извлекаются
булевы регистры, проверки текущего бита и записи в слово. Достижимые остатки
целочисленной арифметики находятся автоматически; далее работает прежнее
ядро вопросов, вынужденных строк и минимального фактора.

| Исходный блок или изменение | Достижимых состояний | Остатки переноса | Необходимых классов |
|---|---:|---|---:|
| Исходный проход | 3 | 0, 1 | 2 |
| Очистка запрещённого бита вместо сложения | 3 | 0, 1 | 3 |
| OR вместо первого сложения | 2 | 0 | 2 |
| Первое сложение с `4 * bit`, записанное `bit << 2` | 4 | 0, 1, 2 | 4 |
| Дополнительный переключающийся флаг, не влияющий на выход | 6 | 0, 1 | 2 |

Последние две строки проверяют разные стороны автоматизации. Число 2 в
переносе появляется из изменённой арифметики, хотя старый клеточный адаптер
допускал только 0/1. Лишний флаг увеличивает физическое состояние, но
необходимый интерфейс остаётся прежним. При изменённом восстановлении
запрещённого бита требуется вопрос с двухразрядным продолжением.

Это заметное расширение автоматического построения исходной модели:
две разные структуры проходов теперь используют общее ядро наблюдений.
Фронтенды и арифметические правила пока различаются: нисходящий проход
использует интервальные вопросы и суффиксные действия, восходящий — остатки
арифметики на границе среза. Единого вывода для произвольных программ нет.

## Какой именно исходник анализируется

Источник — сохранённый `research/graal/native/IntegerStamp.java`, тот же
исходный файл, что в предыдущем этапе. SHA256 исходной версии:
`1a827adb88f57b8f612979af5b90016077cbf4dad4c54b34e539fee5fce01c95`.

Из `computeLowerBound` выбирается единственный возрастающий цикл от нуля
до `bits - 2` вместе с непосредственно предшествующими булевыми
инициализаторами. Точная реализация примитива `CodeUtil.mask` также связана
с сертификатом. Извлечение использует общий токенизатор и парсер Java;
поддержаны переименования переменных, перестановки аргументов коммутативных
операций и эквивалентные обычные/составные присваивания.

Область проверки — этот лексически выделенный блок. Значение слова при
входе задаётся независимо; корректность пути из начала `computeLowerBound`
к этому месту здесь не устанавливается. Внешние сравнения с границей,
предшествующий нисходящий цикл, ветка `optionalBits == 0`, коррекция нуля
и окончательный возврат всего метода остаются за пределами сертификата.

## Контракт и вывод арифметического состояния

Пусть w — положительная ширина полезного слова. Входные M, A, G находятся
в диапазоне от 0 до `2^w - 1`; все обязательные биты M входят в G, а все
биты G входят в разрешённую маску A. Сравнение здесь означает включение
множеств битов. В Java параметр `bits` равен `w + 1`.

Защищаемый ответ — только w младших выходных битов. Конечный перенос,
конечные значения флагов и старшие разряды слова не наблюдаются.
Сертификат не утверждает эквивалентность полного знакового возврата Java.

На границе после k разрядов используется разложение:

`V_k = L_k + 2^k * ((G >> k) + c_k)`.

L_k — уже выданные младшие биты, c_k — целая неотрицательная добавка к
ещё не обработанному исходному суффиксу. До начала прохода `L_0 = 0`
и `c_0 = 0`. Начальные булевы значения берутся из деклараций исходника;
для оригинала это `incremented = false`. Начало не подменяется виртуальным
переносом 1 из прежнего описания фактор-модели.

Запишем `G >> k = g + 2H`. Тогда текущий бит равен `(g+c) mod 2`,
а остаток над ним — `floor((g+c)/2)`. Для прибавления `a * 2^k`
к текущему слову достаточно заменить бит b и остаток h по формулам:

`b' = (b+a) mod 2`, `h' = h + floor((b+a)/2)`.

OR с текущей единичной маской устанавливает b в 1; AND с дополнением маски
устанавливает его в 0; XOR меняет b на `1-b`. Эти операции не меняют L_k
и остальной высокий срез. Условия, читающие текущий бит слова или масок,
и булевы ветвления интерпретируются в исходном порядке. После тела цикла
получается разложение того же вида для k+1.

Это равенства для произвольного H, L_k и k, а не таблица, полученная
перебором коротких машинных слов. Носитель c не объявляется битовым:
производитель строит его достижимое замыкание из операций. Сертификат
содержит происхождение каждого состояния; проверяющий проверяет родителей
и замкнутость под всеми четырьмя допустимыми входными колонками
`(must, may, seed)`.

Индукция по длине слова связывает проверенную конечную систему с
математическим исполнением региона для любой положительной ширины.
Ограниченный фронтенд и приведённые правила разбиения остаются доверенными
компонентами. Это не новая формальная теорема Lean и не доказательство
семантики JVM для всех машинных входов.

## Что переиспользовано из QKF

После получения достижимого носителя используются неизменённые
`producer.py`, `checker.py` и `atomic_rows.py`:

1. Вопросы к выдаваемым битам и их обратные образы уточняют наблюдение.
2. Ядро ответов задаёт фактор состояния.
3. Помеченные атомы обратных строк задают вынужденное продолжение через
   конечные объединения; раздельность атомных образов обосновывает пересечения.
4. Переходы потребителя восстанавливаются из проверенных строк.
5. Для каждой пары разных классов проверяется различающее продолжение.

Так реализован мотив первой статьи: сохраняются помеченные ответы,
а не произвольная заранее выбранная форма внутреннего состояния. Из второй
статьи используется различение недостающего наблюдения и недостающего
обоснования равенства: изменение ремонта требует нового различения,
лишний флаг — нет. Конкретный конечный алгоритм обратного замыкания
и минимизация поведения являются известными приёмами; их самостоятельная
новизна здесь не заявляется.

Новое доверенное пополнение — общий для поддержанного восходящего профиля
разбор и интерпретация локальных операций. Этот фронтенд не обращается к
старой ручной модели переноса. Проверяющий не запускает поиск производителя.

## Проверки

Прошёл 71 тестовый метод: 59 прежних и 12 новых. Общий Java-парсер расширен,
поэтому прежний нисходящий профиль и независимые верхние спецификации
также проверены повторно.

Новые проверки включают 17 повреждений сертификата, изменение исходника,
неподдержанные условия и записи, тип единичной маски `1L`, неверный примитив,
физическое начальное состояние, полноту входного алфавита, обнаружение
переноса 2 и 4, отбрасывание лишнего регистра и явное исчерпание бюджета.
Свежие процессы обычного Python и `-O` воспроизводят сертификат при запрете
импорта производителей, старых адаптеров, Graal-моделей, модулей нативной
проверки, `subprocess` и SMT-библиотек.

Разложение слова дополнительно сопоставлено с прямым исполнением исходного
AST на произвольных высоких хвостах и младших префиксах, в том числе
на границе разряда 127. Это проверка реализации приведённых равенств;
конечные пробы сами по себе не являются универсальным доказательством.

Для каждого из пяти вариантов выполнены:

- Все 5 460 допустимых входа ширины 1–6 битов.
- Ещё 161 вход ширины 8, 16, 31, 32, 33, 61 и 62 бита, включая длинные
  цепочки переноса и отсутствие необязательных битов.
- Сравнение проверенного фактора, отдельного полнословного AST-интерпретатора
  и Java-обёртки с точными байтами исходного блока.

Всего 28 105 вызовов JVM; расхождений наблюдаемого выхода нет. Обёртка
подаёт допустимый вход прямо в выделенный регион. Она не исполняет весь
`computeLowerBound` и не подтверждает его внешние предусловия.

Независимый конечный оракул также перечисляет допустимые числа и проверяет
циклического преемника: минимальное разрешённое число больше G, либо
минимальное разрешённое число при отсутствии большего.

| Вариант | Нарушений этой цели на 5 460 входах |
|---|---:|
| Исходный | 0 |
| Очистка вместо сложения | 822 |
| OR вместо первого сложения | 2 667 |
| Первое прибавление `4 * bit` | 5 334 |
| Лишний флаг | 0 |

Например, для изменённой очистки: w=3, must=0, may=5, seed=1.
Разрешены числа 0, 1, 4, 5; следующий результат должен быть 4,
а изменённый блок возвращает 0. Модель этой ошибочной программы всё равно
сертифицируется как верное описание её поведения — свойство и соответствие
исходнику не смешиваются.

Для восходящего профиля пока нет отдельного универсального сертификата
цели преемника. Ноль нарушений у оригинала относится к конечному оракулу.
Универсальный сертификат нынешней схемы устанавливает соответствие
наблюдений математической модели региона, а не эту независимую цель.

## Воспроизведение и границы

Из корня репозитория, каталог вывода должен быть новым:

```sh
python -m research.observations.run_ascending_experiment reproduction/ascending --native
python -O -m research.observations.ascending_cli check reproduction/ascending/original.java reproduction/ascending/original.certificate.json
```

Для нового поддержанного источника:

```sh
python -m research.observations.ascending_cli derive source.java certificate.json
python -O -m research.observations.ascending_cli check source.java certificate.json
```

Коды выхода: 0 — модель региона сертифицирована, 1 — вход/пакет отвергнут,
2 — бюджет производителя исчерпан без сертификата. Файлы не перезаписываются.
Для проверки сохранённого пакета Java не требуется; она нужна только
нативному эксперименту. Все пять исходников, сертификаты, результаты,
пример исчерпания бюджета и журналы находятся в `evidence/ascending/`.
Эксперимент и повторная проверка добавлены в GitHub Actions.

Профиль ограничен одним изменяемым словом, четырьмя булевыми регистрами,
тестами текущего бита, локальными битовыми записями и сложением с
неотрицательным коэффициентом до 8 при текущей единичной маске. Бюджеты:
64 достижимых состояния, остаток до 255, до 64 классов компактных строк.
Неподдержанное чтение другого среза получает отказ. Ресурсный отказ
не означает неправильность программы или отсутствие конечного наблюдения.

Следующий приоритет — подключить к этому фактору отдельно задаваемую
цель преемника, как уже сделано для верхнего прохода, а затем согласовать
оба профиля под общим пользовательским запуском. После этого можно
заморозить поддерживаемый профиль для внешних примеров и сравнений.
Нынешний этап остаётся исследовательским: новые команды ещё не включены
в устанавливаемый публичный пакет, покрытие KnownBits и Lean не расширено.
