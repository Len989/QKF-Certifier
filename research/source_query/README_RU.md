# PR41: условия, source-факты и первый независимый потребитель

Этот модуль соединяет проверенную семантику выбранного метода с ground-ядром
PR40. Нативные правила дают типизированные равенства E_G; ядро доказывает
равенство исходного Boolean-выражения и независимо заданной цели. Отдельный
checker заново компилирует исходник, проверяет каждый нативный факт и затем
проверяет хронологический ground-proof. Положительному пути не требуется
покрытая residual-модель программы.

Реализован ближайший этап roadmap v0.4. Выбор наблюдений, вынужденность I и
синтез переиспользуемых лемм остаются дальнейшими этапами.

## API

```python
from research.source_query.producer import prove
from research.source_query.checker import check

source = '''class Demo {
    static boolean f(long x) {
        return (((x+x) & 1) == 0) && x >= 0;
    }
}'''
request = {
    'schema': 'qkf-guarded-source-query-v1',
    'target': {
        'schema': 'qkf-target-v2',
        'kind': 'signed_boolean_predicate',
        'source': {'entry': {'class': 'Demo', 'method': 'f'}, 'word_type': 'long'},
        'goal': ['nonnegative'],
    },
    'guards': [],
    'width': {'kind': 'all_positive'},
}
certificate, result, work = prove(source, request)
verified = check(source, request, certificate)
```

`guards` — конъюнкция до 16 формул существующей грамматики `qkf-target-v2`:
sign/popcount-атомы и Boolean `not/and/or/xor`. Например,
`[['nonnegative'], ['not', ['popcount_eq', 0]]]`. Произвольные Java-условия,
пользовательское `x=K`, SMT и новая грамматика здесь не принимаются.

`width` выбирается явно: `{'kind':'all_positive'}` либо
`{'kind':'fixed','bits':64}`. Первый режим означает все положительные ширины
в сохранённой модульной семантике, включая ширины меньше разрядности литерала.
Это не отождествляет Java `long` с переменной аппаратной шириной. Нативная
Java-разрядность соответствует отдельному случаю 64/32. Фактический запуск
Java не используется как доказательство нового пути.

Проверяется всё тело выбранного метода, включая неиспользованные присваивания.
Остальные методы класса не сертифицируются. Контракт прежнего frontend сохраняется:
один однородный `int`/`long` вход, чистые поддержанные операции, сравнения порядка
с нулём; произвольные вызовы, сдвиги и управляющие ветвления не добавлены.

## Нативные основания

| Правило | Что проверяется |
|---|---|
| Равенство и маска | Для настоящих IR-атомов проверяется `(x=K) ⇒ ((x&M)=C)`. В параметрическом режиме требуется `C=K&M`, в фиксированном — равенство после точной редукции по ширине. Условие остаётся внутри импликации. |
| Младший бит | Хронологический вывод двух значений bit₀ каждого нужного word-узла. Проверяются все зависимости и локальные правила операций; постоянный младший бит даёт равенство `(expr&1)=0/1`. |
| Простые word-равенства | Отмена одинаковых операндов, нейтральный ноль, идемпотентность, двойное отрицание/дополнение и точная нормализация константы при фиксированной ширине. |
| Source → target | Сравнение входа с нулём связывается с независимым sign/popcount-атомом. |
| Следствия G | Конечный монитор только целевой абстракции проверяет область G, постоянность target-формулы и случай нулевого входа. Исходные residual-состояния не строятся. |
| Boolean-равенства | Литералы, двойное отрицание, идемпотентность, дополнение и поглощение на конкретных ground-термах. |

Параметрическое обоснование правил приведено в `NATIVE_RULES_RU.md`.
Конечные тесты дополняют проверку правил; они не служат переходом от нескольких
разрядностей к утверждению для всех ширин.

E_G содержит Word/Bool-термы и ровно по одному нативному доказательству каждого
уравнения. Его DAG после сборки равен Sub(E_G) ∪ Sub(O). Ground-query обязан
содержать именно скомпилированный source-root и независимый target-root.
Подмена списка запросов, источника, ширины, G, нативной посылки или ground-proof
не проходит checker. Отдельного API экспорта E_G как безусловной истины нет.

## Значение результатов

| Статус | Значение |
|---|---|
| `certified` | Проверено `G ⇒ source=target` в указанной области ширин. |
| `verified_empty_domain` | Checker доказал пустоту G; ответ явно помечен как вакуозный. |
| `refuted` | Независимое целочисленное исполнение подтвердило конкретное слово, его ширину, выполнение G и расхождение с целью. |
| `unresolved` | Данных правил недостаточно. Разделяющая модель конечного E_G не объявляется контрпримером программы. |
| `unsupported` | Всё выбранное тело не входит в поддержанный source-профиль. |
| `budget_exhausted` | Попытка остановлена по бюджету; частичный положительный proof не выпускается. |

Положительный сертификат достаточен для потребителя. Он не обещает минимального
интерфейса или минимального порога доказательства. Используется обычный режим
entailment PR40.

## Контроль и fallback

`route='ordinary'` получает тот же каталог, порядок попыток, кеш и исходные факты,
но использует обычное нефильтрованное замыкание конгруэнции. Оно выпускает
собственный хронологический proof в формате PR40 и проверяется тем же checker.
Очистка proof от недостижимых событий доступна обоим путям. В эксперименте
сверяются точные ground-input hashes и полные журналы нативных попыток.

По умолчанию после неудачи ground-пути выполняется ограниченный поиск конкретного
свидетеля. Поиск проверяет G до исходного вычисления. Ни отсутствие свидетеля,
ни ground-неследование не дают положительного ответа.

`fallback=True` явно разрешает сохранённую покрытую source-конструкцию. После
неё используется **новый** product-monitor, проверяющий G и область ширины.
Старый безусловный target-verdict не подставляется в условную задачу.
Для фиксированной ширины после неё существует явно проверяемый поглощающий
узел вне области обязательства. В proof положительного fallback сохраняются
source-сертификат и полное замыкание product-состояний.

Затраты неудачной первой попытки остаются в `work`, а её проверяемая
ground-модель — в `prior_ground_evidence`, когда итоговый путь сменился.
Стоимость всей сборки и проверки fallback учитывается. Проверка portable
сертификата не доверяет `work`, cached receipt или сохранённому вердикту.

## Границы и учёт работы

Основные defaults: 10 000 нативных попыток, 2 млн входов в Python-функции
research-модулей, поиск свидетеля до 8 бит и 510 проверяемых кандидатов,
до 64 source-классов и 8192 product-состояний при fallback.
`limits` позволяет менять эти пределы в разрешённых границах.
Бюджет кандидатов включает отсеянные по G слова; их число и реальные source
evaluations показываются отдельно. Для фиксированной ширины больше 8 нужно
явно поднять `max_witness_width`, чтобы включить этот ограниченный поиск.

Ground-DAG ограничен 4096 узлами; действуют также ограничения схемы PR40.
Грамматика и размеры source-IR остаются прежними. Фиксированная ширина и конкретный
witness ограничены 4096 битами. Параметрическое положительное доказательство
охватывает все w≥1 без верхнего предела и не перебирает ширины.

Профилирование фиксирует реальные входы в функции, включая импортированные
алиасы; на native-пути вызов старых source-builder вызывает жёсткую ошибку.
Нативные кандидаты имеют явный журнал успехов, неуспехов, cache hits и остановок.
Проверки guard-domain при replay также учитываются. Это диагностика текущего
процесса, не криптографическое свидетельство его исполнения и не sandbox от
враждебного monkeypatching.

Instrumented elapsed time включает семантическую подготовку и встроенные
проверки; исключает сериализацию диагностики, CLI I/O и отдельный внешний replay.
Здесь нет рейтинга ускорений. На зарегистрированных случаях простой контроль
совпадает с новым путём по результатам и размеру конечных сертификатов.
Вклад новых правил не приписывается автоматически I/II.

## Воспроизведение

```sh
python -m research.source_query.cli prove source.java request.json certificate.json
python -O -m research.source_query.cli check source.java request.json certificate.json
python -m unittest research.source_query.test_source_query -q
python -O -m unittest research.source_query.test_source_query -q
python -m research.source_query.experiment NEW_DIRECTORY
python -m research.source_query.replay NEW_DIRECTORY
python -O -m research.source_query.replay NEW_DIRECTORY
python -m research.source_query.preserve
```

CLI: код 0 — `certified` либо явно пустая область, код 1 — refuted/unresolved/
unsupported/budget, код 2 — ошибка входа/сертификата/файла. Выходной сертификат
создаётся эксклюзивно и не перезаписывает существующий файл. У unsupported/budget
новый сертификат отсутствует. У unresolved имеется проверяемая ground-модель.
Режим `check` не загружает discovery-код. Публичный установленный `qkf` не изменён.

Fresh replay запрещает producer/closure/SMT imports и уже загруженные search-модули,
перепроверяет все имеющиеся сертификаты, предыдущие ground-попытки и source
admission для unsupported. Budget-диагностика не переисполняется. Отдельный
тест выполняет native-checker с запретом всех legacy source-interface модулей.

Точный корпус и условия эксперимента — `REGISTRATION.json`, `PROTOCOL.json`.
Результаты и границы выводов — `VALIDATION_RU.md`. Текущий CI запускает новые
и прежние регрессии, эксперимент и normal/`-O` replay на Python 3.10/3.12.
