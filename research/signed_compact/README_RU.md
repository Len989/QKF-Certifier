# PR37: компактные доказательные зависимости и разделение по запросу

## Задача и достигнутая граница

PR36 устранил повторное восстановление общей посылки в одной сессии, но каждое
переносимое доказательство всё ещё включало всю source-зависимость и все попарные
разделяющие продолжения. PR37 меняет представление этой информации, не грамматику,
семантический контракт, алгоритм наблюдений или лимит 64 состояний.

Новый пакет хранит один source/reduction/coverage/observation интерфейс для 1–64
независимых целей одного метода/типа. Одинаковые JSON-подструктуры (включая IR,
проекции и повторные таблицы) представлены одной записью DAG. Попарные слова не
хранятся: их обосновывают ранее проверенные происхождения вопросов. Конкретная пара
разворачивается только по запросу или при явном экспорте старого формата.

Это **синтаксическое разделение одинаковых данных**, а не отождествление программ
по одному хешу или ядру. Метки, начальная точка, все guards/ветви, строки и независимо
заданные цели по-прежнему проверяются. DAG данных не следует путать с глубиной
равенства lambda из статьи II. Никакой новой оптимальности по этой глубине нет.

## Точные схемы и API

Транспорт: `qkf-json-proof-dag-v1`. Его корень разворачивается в
`qkf-signed-compact-target-bundle-v1` с полями `selection`, `source`, `items`.
Источник: `qkf-signed-guarded-compact-observations-v1`; finite-доказательство:
`qkf-derived-observation-implicit-v1`, policy
`first-differing-derived-question-v1`. Целевой результат:
`qkf-signed-compact-target-result-v1`, engine `signed-compact-coverage-v1`.
Это новый явно обозначенный формат, не неполный старый сертификат.

```python
from research.signed_compact.producer import prove_many, pack_proofs
from research.signed_compact.checker import load, check, export_legacy

results, packet = prove_many(source, targets, budgets={"max_states": 64})
# packet is None if any requested target lacks a complete proof.
verified = load(source, targets, packet)
results = verified.results()
explanation = verified.explain_pair(0, 1)
legacy = export_legacy(source, targets, packet, index=0)
```

`targets` — массив из 1–64 отдельно заданных signed-целей `qkf-target-v2`.
`load` проверяет всю общую посылку один раз, затем каждое обязательство. Новый target
может отдельно проверяться через `verified.check_obligation(target, obligation)`.
Объект неизменяемый, возвращаемые словари отделены, pickle/создание из receipt
запрещены. Это обычная гарантия Python API, не sandbox против reflection/monkeypatch.

`pack_proofs` сначала проверяет каждое старое доказательство и требует одну и ту же
полную source-зависимость. Только затем удаляет дубли и явные separators.
`prove_many` использует существующий PR36 batch; **discovery пока создаёт старые
полные пакеты, включая transient separators**. Экономия памяти поиска не заявляется.
При неполном результате общий пакет не выпускается, отдельные результаты остаются
диагностикой. Разрешённые старые search-бюджеты не увеличены.

```sh
python -m research.signed_compact.cli prove Source.java --targets targets.json --proof compact.json
python -m research.signed_compact.cli check Source.java --targets targets.json --proof compact.json
python -m research.signed_compact.cli pair Source.java --targets targets.json --proof compact.json --left 0 --right 1
python -m research.signed_compact.cli export Source.java --targets targets.json --proof compact.json --index 0 --out old.json
```

Новые выходные пути создаются эксклюзивно. Повторные/nonfinite JSON-ключи/значения
отвергаются. Коды: 0 — все цели подтверждены или pair/export выполнены, 1 — есть
проверенное опровержение, 2 — unresolved/unsupported, 3 — невалидный сертификат,
64 — ошибка ввода, 70 — внутренняя ошибка. Итоговый список всегда содержит отдельные
результаты; mixed-статус не означает, что все требования истинны.

## Почему не потеряна точность фактора

Finite-checker — отдельно обозримая atomic-специализация проверок прежнего
`observations.checker`; старый файл сохранён. Переиспользуются `Model`, строгая
типизация, atomic completion и row primitives. Новый код не исполняет текст прежнего
checker динамически. Его обязательства сравниваются с прежним на случайных конечных
моделях и на всех development-пакетах.

1. Каждый исходный вопрос — проверенный terminal/output предикат. Pullback содержит
   ссылку на строго более ранний вопрос и проверенную маску его прообраза.
2. Предложенные блоки покрывают носитель ровно один раз и совпадают в точности с
   ядром ответов на вопросы. Конечные метки и все переходы постоянны на блоках.
3. Нативные атомные прообразы, их completion и восстановленные cells проверяются
   точно так же по исходной модели, а не доверяются данным генератора.

Индукция по происхождению вопроса даёт конечный контекст: terminal соответствует
пустому слову, output — одному символу, pullback дописывает свой символ слева.
Любое устойчивое разбиение, сохраняющее outputs/terminals, делает каждый такой
вопрос постоянным на своих блоках. Поэтому оно уточняет проверенное разбиение.
Проверенная устойчивость даёт обратную достаточность: получен **наиболее грубый
устойчивый фактор именно этой модели и этого потребителя**. Не нужен список всех
пар, поскольку различие сигнатур уже гарантирует вопрос для каждой пары.

`explain_pair` выбирает первый различающий вопрос, разворачивает только его цепочку
предков, затем проверяет полученный контекст на каждом представителе обоих блоков.
Это свидетельство невозможности их объединения; не upstream-ошибка, не доказательство
минимального числа вопросов и не кратчайшее разделяющее слово. Root `not-a-word`
сохранён отдельно. Неразличимые классы нельзя искусственно дробить.

## Source/target связь и доверие

Неизменённый PR35 `rebuild` заново разбирает источник и проверяет reduction, все
условные производные, полноту покрытия и terminals. После нового finite-check
создаётся прежний immutable Runner из проверенных атомных строк. Цели проверяются
прежним PR31 `check_product` и PR36 `check_ir`; источник/цель/ширина отрицательного
свидетеля не подменяются. Положительное произведение не исполняет слова исходника.
Целевые входы повторно передаются пользователем и сравниваются со всеми item targets.

Fresh replay не вызывает старый finite-checker, producer, SMT или Java, не строит
все separators и не запускает поиск. Старый checker может импортироваться как
транзитивная зависимость переиспользованного Runner, но не вызывается. Запрет вызовов
и нулевое число материализаций проверяются профилированием, не предположением о
структуре импорта. Общая source-посылка проверяется один раз на весь пакет.

Новый результат содержит `target_checked: true`, `source_interface_verified: true`,
`lean_checked: false`; `all_positive_widths` истинно только для положительной цели
в принятом модульном профиле. Small-width counterexample не превращается в Java bug.
Доверяются ограниченный frontend, семантика, checker reduction/coverage/rows, новый
finite-validator/DAG-decoder и Python. Новой Lean-теоремы или общего Paper I kernel нет.

## DAG и ограничения декодера

Записи `v`, `l`, `d` содержат соответственно типизированный scalar, список индексов
или упорядоченный список пар ключ/индекс. Каждая ссылка строго меньше текущего
индекса: отсутствующие/циклические/forward ссылки отвергаются до декодирования.
Boolean не считается integer-индексом. Float, код, нестроковые и повторные ключи,
дубли записей и недостижимые записи запрещены.

Лимиты: 100000 записей, глубина 128, 5000000 байт wire и развёрнутого payload.
Размер развёртки рассчитывается снизу вверх **до выделения decoded контейнеров**;
повторные ссылки учитываются с кратностью. Поэтому маленький DAG не скрывает
экспоненциальную развёртку. Декодер восстанавливает обычный ограниченный JSON;
zero-copy checking или снижение пикового decoded heap здесь не заявляется.

`export_legacy` намеренно восстанавливает все старые separators и заново проверяет
старый target-пакет. Это не скрытая стадия компактного replay. Результат принимает
неизменённый v6. На канонических пакетах нынешнего producer экспорт побайтово
совпадает; для произвольного valid old proof сохраняются утверждение и действие,
но не произвольный выбор прежних свидетелей/их хешей. Прежние схемы не переключены.

## Development-проверки и измерения

49 новых тестов и 485 предыдущих выбранных регрессионных тестов — обычно и под -O.
Это не всё множество pytest репозитория. Проверяются атакующие DAG, строки, guards,
происхождения вопросов, target binding, ложные cached receipts, экспорты и isolated
процессы. 80 seeded конечных моделей сравниваются с прежним finite-checker; все их
парные объяснения также совпадают.

Эксперимент: 8 прежних context-источников плюс сравнения с 2^4, 2^8, 2^30, 2^40;
12 источников × 4 требования = 48 пакетов-целей, с намеренно неверными требованиями.
В compact transport это 12 shared bundles плюс 12 отдельно проверяемых single.
Отдельно сохраняются legacy пакеты/экспорт, query explanation, все затраты и manifest.
Из preceding context-experiment берутся 2086 Java-записей; compact-эксперимент
перепроверяет их, но сам Java не запускает. В CI preceding context experiment
создаёт эти записи заново. Новые equality-случаи проверяются по IR, не Java.

```sh
python -m research.regression.run --group new
python -O -m research.regression.run --group new
python -m research.regression.run --group prior
python -m research.signed_compact.experiment NEW_DIR --input EXISTING_CONTEXT_EXPERIMENT
python -O -m research.signed_compact.replay NEW_DIR
```

Отдельные размеры single/four не смешиваются; время legacy preparation, packing с
проверками, decoder, replay, explicit export и одного warm pair учитывается отдельно.
В storage comparisons перечисляются полные certificate bytes обеих версий; внешний
исходник и независимо передаваемые targets являются входами обеих сторон. Отчёт
результатов и тестовая копия legacy-пакетов не считаются частью deployed certificate.
Ни размер ZIP, ни число сжатых записей не выдаётся за сложность вывода наблюдений.
Первый локальный тест ошибок содержал две неверные проверки стенда: подмена нуля
тем же нулём и запрет транзитивного импорта вместо запрета вызова старого checker.
Они исправлены до публикации; первоначальный журнал сохранён в контрольной точке.

Прежний current-research workflow расширен шагом compact; новый архивный workflow
не создан. Реестр перемещает context/registry тесты в prior и включает compact в new.
Дополнительный audit сохраняет 1968 других файлов принятого PR36. Исторические
1/15, 2/33 и сравнение PR32 не пересчитаны. Все случаи остаются development-набором.
Следующий согласованный шаг — общий certifying-слой вынужденности (плановый PR38).
