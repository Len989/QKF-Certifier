# PR47 — равные SDK-контроли и полная стоимость

Ordinary PR41 с полноценной SDK-обёрткой дешевле SDK default во всех четырёх основных одиночных задачах на каждой из двух версий Python. Для зарегистрированной серии эквивалентных consumer-запросов основной простой контроль — `once_ordinary`: построить первую сводку, проверить её в новом процессе и выполнить `assess` всех запросов. Алгоритмы вывода и SDK defaults сохранены.

Это сравнение уже доступных способов получения нужного результата. Индивидуальные native-доказательства всех целей у batch-пакета — дополнительная возможность; сервисный assess-ответ не является самостоятельным сертификатом каждой цели.

## Самостоятельные сертификаты каждой цели

Каждый packet проверяется независимо. Builds выполняются последовательно внутри одного свежего процесса, с естественной амортизацией импорта. Эти зарегистрированные клиенты не сохраняют межвызовный semantic/exact cache. Клиент, сохраняющий сертификат точного повтора, может быть дешевле; такой контроль требуется зарегистрировать до заявления о превосходстве на standalone exact repeats в PR52.

## Отрицательные исходы и границы

На каждой Python версии исходы по 164 парам: `budget_exhausted` — 1; `certified` — 129; `refuted` — 12; `unresolved` — 16; `unsupported` — 3; `verified_empty_domain` — 3.

Все девять signed diagnostics и шесть phase cases сохранены. Конкретное опровержение перепроверяется по witness; empty G не считается полезным положительным результатом. Unsupported и resource budget без packet остаются непроверяемыми поисковыми диагностиками и не используются как semantic premises.

Новый assessment case подтвердил эквивалентную цель и вернул unresolved для ложного consumer, изменённых G, width, selection и другого profile. Несогласие consumer-класса не объявлено конкретным source counterexample. Мутации source/packet/request покрыты тестами. Search imports в CI replay — 0; полное source-исполнение в положительной проверке и apply запрещено.

Phase сохранён отдельной группой со своими forcing/no_saturation/direct_seeds/direct_cell. Все её samples и экономические строки находятся в RESULTS.json; signed PR41 не считается её matched baseline. Новых forcing theorem нет.

## Решение для PR48–52

Контроли зафиксированы в [PR52_BASELINES.json](PR52_BASELINES.json) до оптимизаций. Во всех применимых CI shards и обеих версиях Python зарегистрированное правило выбора даёт один и тот же маршрут. Дополнительно ordinary имеет меньшую медиану в каждой соответствующей строке: 4/4 одиночных, 13/13 once-сервисных и 13/13 standalone на каждой версии. Поэтому выбор не зависит от объединения численных сумм разных runners; такие суммы не публикуются.

- `single_summary`: `sdk_ordinary`.
- `consumer_service`: `once_ordinary`.
- `independent_certificates`: `each_ordinary`.

PR48 устраняет повторную подготовку одного проверенного контекста, PR49 — промежуточную упаковку. Их приёмка должна учитывать полный одинаковый контракт и простой контроль. В PR52 сохраняется матрица ordinary/query × no_lemmas/reuse с одинаковыми native policy, caches и packaging.

Практический gate PR52 остаётся прежним: ≥20% медианы и ≥1 мс singleton / ≥10 мс series N≥4, максимум кандидата ниже минимума baseline на заявленной строке, без потери корректности/покрытия и без >10% ухудшения build Python peak без отдельного tradeoff. Меньшее число calls или packet bytes само по себе gate не закрывает. Это критерий данного development-корпуса.

SDK defaults сохранены. F1 остаётся открытой. Карточка цельного KnownBits_Add с точными исходниками и границами находится в [PILOT_RU.md](PILOT_RU.md); новый frontend и SDK-доказательство целого трансформера в PR47 не реализованы.
