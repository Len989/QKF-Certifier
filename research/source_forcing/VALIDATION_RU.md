## Результат

`7a4b84d92654ef22c911dab503efd829b48a72156ff0de51129e767589ad0010`
и label `(0,1,1,0)` независимо проверены:

- physical branch proofs `A→(0,C), B→(1,B), C→(0,C)`;
- четыре source-bound seed: `0→0, 2→0, 6→5, 7→5`;
- смысл всех восьми элементов и 128 записей union/intersection;
- гомоморфность фактического guarded inverse image и identity descent;
- `S={0,2,6,7}`, `D={0,1,2,3,4,5,6,7}`, `h(3)=0`, `3∉S`;
- portable consumer proof без прямого запроса `h(3)` и без global source quotient.

Только source-local утверждение: при этом guard нельзя одновременно получить
выход 0 и следующую фазу без физического carry. Whole-word/signed перенос
не доказан. Trace защищает фактические вызовы именованных запрещённых операций;
это диагностика, а не аттестация произвольного исполнения Python.

## Решение A1

Механизм `D>S` принят в отдельном локальном профиле. Круговой выдачи заранее
вычисленной action-ячейки за forced-ответ нет. Но три физических перехода,
достаточные и для прямого ответа, уже целиком построены ради seed и оплачены.
Само отсутствие вызова `h(3)` не означает экономию source reasoning.

Прямой контроль на **тех же** четырёх seed выводит атомарные образы
`h(A)=h(ABC)\h(BC)`, `h(B)`, `h(C)=h(BC)\h(B)`. В пилоте это сразу даёт
`h(A∪B)=∅`. Поэтому полезность I как ускорителя здесь не подтверждена даже
с учётом reuse. Forcing сохраняется как проверяемый механизм для дальнейших
исследований; расширение допускается лишь при отдельном оправдании затрат
подготовки и новым честным сравнении. Для данного пилота рекомендован direct.
Поле `default_route` в решении A1 — рекомендация будущему planner;
экспериментальная CLI по умолчанию демонстрирует forcing.

PR43 продолжает query/planner/reuse; положительный результат I не объявляется
его условием. Никаких новых продуктовых обещаний для основного signed-профиля
из этого локального результата не следует.

## Журнал исправлений до публикации

Первый smoke вызов остановился при импорте Python-класса `subprocess.Popen`:
call guard ошибочно считал определение класса запуском процесса. Guard уточнён
до вызова конструктора; запуск внешних процессов на этом маршруте не требуется.
Проверка не выдала ошибочного сертификата.

`pr42_01` сохранён с `FAILURES.json`: запись первой диагностики остановилась,
поскольку строгий JSON writer не принимает float seconds старого pure-row
producer. Длительности переведены в integer nanoseconds. Набор случаев,
ожидаемые исходы, source, цели и правила не менялись.

`pr42_02` полностью прошёл comparison и fresh normal/optimized replay.
После review поле счётчика переименовано из `goal_derivations` в `distinct_goals`:
forcing делает lookup уже выведенной строки, поэтому прежнее название было
неточным. Consumer lookup получил явный кеш. `pr42_03` повторяет неизменённую
регистрацию, имеет тот же semantic summary hash и сохраняется отдельно.
Ни один неудачный запуск или случай не исключён задним числом.
