## Что именно формально проверено

`Core.lean` задаёт типизированный интерпретатор целевых наблюдений, полный
шестиколонный алфавит допустимых входов и независимого конкурента, конечный
сертификат замкнутости и теорему о произвольном конечном списке колонок.

`Numeric.lean` связывает наблюдения с накоплением числовых слов по разрядам:
равенством, порядком и поточечным включением/непересечением масок. Общая теорема
`numerical_formula_all_widths` применяется к заданному фактору, программе
наблюдений и принятому сертификату, при положительной длине и указанной
предпосылке формулы. Никакой заранее выбранной физической модели переноса
в этом общем механизме нет.

`cyclic_successor_all_widths` устанавливает числовые обязательства фиксированной
формулы преемника для каждого непустого списка допустимых колонок: законность
выхода, строгое продвижение при немаксимальном входе, сравнение с независимо
выбранным большим конкурентом и возврат к обязательной маске при максимальном
входе. `cyclic_extrema_characterization` отдельно доказывает числовой аргумент
о существовании большего элемента и возврате при его отсутствии, со всеми
предпосылками о допустимом множестве в формулировке.

`Exported.lean` содержит две явные исходные машины, экспортированные из
проверенных пакетов для `original` и `irrelevant_register`, и применения общих
теорем к ним. Каждая имеет два класса источника, девять совместных состояний
и 54 перехода. Девятое состояние отличает пустую инициализацию от положительной
длины. Минимальность числа состояний не заявляется.

Старые Python-сертификаты источника заново проверяются на этой ветке.
`check_ci.py` сверяет каждый начальный индекс и все восемь клеток экспортированной
машины с проверенным исходным фактором. Это исполняемая Python-связь с Java,
а не формальное доказательство корректности парсера. Хеши фиксируют идентичность
байтов, но не заменяют проверку доказательства.

## Аудит аксиом и отрицательные проверки

Все десять проверенных теорем зависят только от `propext` и, для числовых
теорем, `Quot.sound`. `Classical.choice`, `sorryAx` и дополнительные аксиомы
отсутствуют в принятом результате. Статический поиск сокращённых доказательств
выполняется дополнительно, но не выдаётся за аудит Lean.

Пять независимых свежих сборок получили ожидаемый отказ `decide` на ложном
обязательстве, а не на синтаксической ошибке:

| Изменение | Место отказа |
|---|---|
| Начальный индекс сертификата | `Accepted machine program certificate` |
| Один переход сертификата | `Accepted machine program certificate` |
| Один выход исходной машины | `Accepted machine program certificate` |
| Подмена защищённой цели константой true | `program = successorProgram` |
| Проекция входной колонки | `Accepted machine program certificate` |

Шестой контроль заменяет доказательство принятия на заглушку только во временной
копии. Lean допускает её с предупреждением, но реальный вывод аудита содержит
`sorryAx`; наш обязательный аудит отвергает такой результат. Эта временная
заглушка отсутствует в опубликованных математических файлах.

## Что пришлось исправить при реальном запуске

Первый запуск остановился до компиляции из-за отсутствующего манифеста Lake.
Затем обнаружились ошибки конкретных Lean-доказательств: вычисление с локальной
переменной, отражение булевого равенства, несовпадение форм представления формулы
и недоступная тактика доказательства от противного. Их исправления не ослабляли
формулировки теорем и не меняли экспортированные машины/сертификаты.

Промежуточная версия полностью компилировалась, но зависела от
`Classical.choice` в специализации формулы. Вместо расширения разрешённого
набора аксиом использована конечная булева лемма отражения с проверкой по
конструкторам. Только после этого строгий аудит и все отрицательные контроли
прошли. Успешная сборка промежуточного коммита не объявляется полной приёмкой.

## Воспроизведение и границы

В полной копии этой ветки, при установленном инструментальном наборе Lean 4.33.0:

```sh
python -O research/lean_targets/check_ci.py --output reproduction/lean_target_check_01 --timeout 300
```

Путь вывода должен быть новым. Отсутствие инструментов, исчерпание общего
бюджета, неудача сборки или аудита не дают принятого результата. CI имеет
также собственный общий лимит времени. Журналы и, в последующем варианте
workflow, точные проверенные исходники сохраняются артефактом.

Ветка создана от `main` после PR 5: `8e482b2f2f7343af24a8c5a2e3a17867e3bd7ae7`.
Она публикует самостоятельный формальный проект. Она не публикует скрыто всю
локальную реализацию прогонов 2 и 3 и не закрывает их оставшиеся задачи CI.
Исходный старый Lean-пилот, стабильные проверяющие, `main` и настройки GitHub
не изменены этой работой.

Принятая формализация относится к явному исходному фактору и числовому смыслу
целевых наблюдений. Это не доказательство Python-фронтенда, полного
`computeLowerBound`, `IntegerStamp.create`, знаковой семантики JVM или
композиции из прогона 3. Формальный компилятор произвольных JSON-спецификаций
также не заявляется. Локальная полная база и удалённая отдельная ветка имеют
разный объём; их результаты не следует смешивать.
