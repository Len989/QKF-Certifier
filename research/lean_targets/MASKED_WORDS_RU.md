# Точный числовой преемник из принятого целевого сертификата

Этот этап добавляет `QKFTarget.Masked` поверх неизменённых `Core`, `Numeric` и
`Exported` проекта `research/lean_targets`. База — `main` после PR №12,
`7d4f03fae3ef66410f8ce0fe1282bc68fc3b9faa`. Идея представления каждого
конкурента и независимости выхода перенесена из `Words.lean` PR №7
(`d2f727fc3678273bb8f19f185201f7b8b01306ad`), но второе ядро из №7 не используется.

## Что именно формализовано

`Input = Fin 4` — все четыре законных тройки одного разряда
`(must, may, seed)`: `000`, `010`, `011`, `111`. `inputMust`, `inputMay`,
`inputSeed` декодируют их. Существующий `Column = Fin 6` дополняет вход
независимым законным битом конкурента. Три теоремы `project_*` проверяют
соответствие декодирования прежней проекции.

Списки хранят младшие биты первыми. `value (b :: bs) = digit b + 2 * value bs`.
`value_snoc` связывает эту запись с накоплением по весам `2^position` из
`Numeric.lean`; `Represents` и `executed_value` доказывают соответствие после
любого числа шагов, а не только на экспортированных коротких примерах.

`emitted` принимает только список исходных входных колонок. Конкурент не
является его аргументом. `output_independent` доказывает равенство числового
выхода любых двух колонковых трасс с одинаковой проекцией на входы.

`AdmissibleBits is bs` задаёт ровно законные биты и одновременно одинаковую
длину входа и кандидата. `Masked is z` означает существование такого списка
`bs` с `value bs = z`. Определение множества не вызывает программу и не
пользуется сертификатом. Это **числовое множество через законные битовые
списки**, не ссылка на внешнюю реализацию `BitVec` или недоказанное равенство
с библиотечными `Nat.land`/`Nat.testBit`.

`encode_columns` представляет любой такой кандидат полными колонками,
сохраняя исходный вход. `masked_extrema` выводит принадлежность минимума и
максимума и числовые границы каждого элемента. `greater_exists_iff` доказывает,
что больший элемент существует ровно тогда, когда начальное число не равно
разрешённой маске. Непустота не постулируется: минимум явно принадлежит носителю.

## Итоговый контракт

Для `L = Masked is`, `G = value (is.map inputSeed)`,
`M = value (is.map inputMust)` и `Y = value (emitted m m.initial is)`:

- `Y` принадлежит `L`;
- если существует `Z` из `L` с `G < Z`, то `G < Y`, и для каждого такого `Z`
  выполняется `Y <= Z`;
- если большего элемента нет, `Y = M`.

`exact_cyclic_successor` выводит этот контракт из существующего
`Accepted m successorProgram cert` для **каждой положительной длины** `is`.
В итоговом утверждении нет выбранного слова-конкурента: он квантифицирован
внутри контракта над полным множеством допустимых чисел.

`original_exact` и `irrelevant_exact` применяют доказательство к двум уже
экспортированным факторам. Данные не изменены: у каждого 2 класса источника,
9 совместных состояний и 54 перехода. `cyclic_successor_unique` доказывает
единственность ответа; `original_irrelevant_same` даёт равенство результатов
двух факторов для каждого положительного входа без сравнения их таблиц.

## Приёмка и воспроизведение

Из корня чистого checkout, при наличии закреплённого Lean 4.33.0:

```sh
python -O research/lean_targets/check_masked.py --output reproduction/exact_masked_01 --timeout 300
```

Каталог вывода должен быть новым. Проверяющий сценарий повторно связывает
машины с исходниками, собирает проект в новой временной директории без `.lake`,
проверяет **16 перечисленных теорем**, а затем **8 семантических контролей**.
Для каждого дефектного утверждения сначала Lean доказывает, что условие ложно,
потом отдельный запуск должен отвергнуть утверждение его истинности.
Недостающий импорт, ошибка синтаксиса, тайм-аут или ресурсное ограничение не
считаются нужным отрицательным результатом. Положительные контроли включают
пропуск в носителе `{0,1,4,5}`, циклический возврат, одноэлементные маски и ширину 1.

Дефекты: неполный алфавит, конкурент подменён начальным битом, зависимость
выхода от конкурента, неправильная проекция входа, обратный порядок битов,
возврат максимума вместо минимума, замена преемника одной принадлежностью
маске, утрата ограничения длины. Ещё один контроль заменяет доказательство
в **отдельной временной копии** заглушкой: сборка может пройти, но реальный
аудит обязан отвергнуть её зависимость.

Разрешённые аксиомы — только `propext` и `Quot.sound`. Имена и количества
аудируемых теорем заданы независимо в сценарии. Отсутствие инструмента даёт
`unavailable`, а не успех. Полная приёмка требует `status: accepted`,
`lean_checked: true`, код выхода 0 и завершённые отрицательные контроли.
Сам Python-сценарий не является доказательством.

Workflow `Exact masked successor` получает пакеты заново, экспортирует данные
из них, проверяет побайтное равенство с компилируемым `Exported.lean`, затем
запускает новый сценарий. Журналы, точные проверенные Lean-исходники, идентификатор
дерева, пакеты и итог сохраняются в артефакте на 30 дней. Успех старого
`lake build` без явной сборки `QKFTarget.Masked` не заменяет эту приёмку.

## Границы

Это усиление формальной связи уже существующего фактора с полным числовым
контрактом, не новый алгоритм преемника и не расширение внешнего покрытия.
Полезные леммы №7 адаптированы, но весь №7 не слит и не объявлен избыточным.
Java-парсер, правила разбиения исходного слова, Python-проверяющие, трансляция
JSON и экспортёр не стали Lean-верифицированными. Схемы сертификатов, целевые
формулы и все прежние математические файлы остаются неизменны. Новая теорема
не доказывает композицию №12, знаковую JVM или весь `IntegerStamp.create`.
