# Условная композиция: максимум снизу и преемник дают минимум сверху

База: `09f1860c6470d4c867dee99b39f2614840f1fa1f`, после PR №14.
Новый слой — `QKFTarget.Ceiling` поверх принятого `QKFTarget.Masked`.
Отложенный `research/wordexpr` не используется. Старые определения, таблицы,
сертификаты, фронтенды и интерпретатор композиции остаются без изменений.

## Математический контракт

Для множества натуральных чисел `L`, его минимума `minimum`, максимума `maximum`
и границы `bound` результат имеет тип `Option Nat`:

- `some y` означает `L y`, `bound <= y` и `y <= z` для всякого `z` из `L`
  с `bound <= z`;
- `none` означает, что каждый `z` из `L` строго меньше `bound`.

`ExactCeiling` не использует вычисляемую программу для определения множества.
Теорема `empty_iff_no_candidate` доказывает эквивалентность пустого результата
отсутствию подходящего элемента; `exact_ceiling_unique` — единственность всего
помеченного ответа. `some 0` не равен `none`.

Числовая функция `compose` повторяет ветвления опубликованного примера:
если граница строго ниже минимума, вернуть минимум; если строго выше максимума,
вернуть пустоту; иначе вычислить нисходящий максимум `g`; при `g = bound`
вернуть `g`, иначе запустить преемника с начальным значением **именно `g`**.
Сравнение в первой ветке строгое, как в `composition_example.json`: при равенстве
границы минимуму выполняется вызов нисходящего прохода.

## Общее правило и оставшаяся предпосылка

`FloorContract L b g` требует принадлежности `g` множеству, `g <= b` и
максимальности среди всех допустимых `z <= b`. Одной принадлежности или
соблюдения границы недостаточно.

`SuccessorContract L minimum g y` требует принадлежности `y`, точного наименьшего
элемента выше `g` при его наличии и возврата минимума при отсутствии большего.

Теорема `compose_correct` параметризована **произвольными** числовыми функциями
`floor` и `next`, доказанными экстремумами `L` и указанными контрактами. Контракт
`floor` нужен лишь для `minimum <= b <= maximum`. Ветви за пределами этой области
не требуют корректности вызова, который не производится.

Центральная лемма `floor_then_successor`: при `g < bound <= maximum` законный
максимум является свидетелем существования числа выше `g`, поэтому преемник не
может циклически вернуться. Он законен и больше `g`. Если бы `y <= bound`,
универсальная максимальность первого прохода дала бы `y <= g` — противоречие.
Следовательно, `bound < y`. Для каждого законного `z >= bound` также `g < z`,
и минимальность преемника даёт `y <= z`.

**Контракт самого нисходящего Java-региона не формализован этим PR.** Он остаётся
явной гипотезой, а не новым постулатом/аксиомой и не автоматически принятым фактом
из Python-сертификата. Общая теорема доказывает композицию при этом контракте.
Чтобы показать содержательность предпосылок, отдельно доказаны универсальные
контракты явных функций для `L = {0,1,4,5}` и правильность их композиции при любой
натуральной границе (`four_element_example_all_bounds`).

## Масочный мост и реальные принятые факторы

Масочное множество остаётся прежним `Masked is z`: число представлено законным
битовым списком **той же длины**, младшими битами вперёд. Это не неявное равенство
с библиотечными `Nat.land`, `BitVec` или машинными Java `long`.

`SameMasks` требует поразрядного совпадения обеих масок. `admissible_same_masks`
и `masked_same_masks` показывают, что начальное слово не меняет носитель.

`OptionalBits` разрешает выбирать только необязательные биты `may && !must`;
`fillOptional` присоединяет обязательные биты. `optional_decompose` строит
обратное представление для любого законного слова. `masked_iff_extensions`
доказывает точное равенство числового множества с множеством таких расширений.
Это связывает два математических описания носителя при начальном значении `must`.

`bitsOf` детерминированно получает разряды числа. `bitsOf_value` и `bitsOf_masked`
доказывают правильность этой операции на законных словах, без выбора произвольного
представления. `reseed_facts` доказывает сохранение масок и длины и точную передачу
нового начального слова. Незаконное число не считается допустимым только потому,
что `bitsOf` обрезает его до ширины: теорема требует `Masked is g`.

`nextFrom` запускает **существующую** явную машину на перестроенном входе.
`nextFrom_correct` выводит её точный числовой контракт из принятой ранее теоремы
`exact_cyclic_successor`. `masked_compose_correct` соединяет этот результат с
условным нисходящим контрактом. `original_ceiling` и `irrelevant_ceiling`
специализируют его к двум неизменённым экспортированным факторам.

Итоговая масочная теорема относится ко всем положительным длинам и всем
натуральным границам; обычная область типизированных границ входит в неё.
Свойства `must`, `may`, носителя и переданного `g` выводятся, а не добавляются
как новые внешние предположения к существующему восходящему сертификату.

## Реальная формальная приёмка

При установленном закреплённом Lean 4.33.0, из корня checkout:

```sh
python -O research/lean_targets/check_ceiling.py --output reproduction/ceiling_review_01 --timeout 300
```

Нужен новый каталог вывода. Сценарий заново воспроизводит привязки исходных
машин, копирует формальный проект без `.lake`, явно собирает новый модуль,
проверяет **22** именованных теоремы и **8** отрицательных семантических условий.
Для каждого сначала требуется настоящее доказательство ложности, затем другой
запуск Lean должен отвергнуть ложное утверждение истинности. Ошибки синтаксиса,
импорта, отсутствие инструмента или исчерпание времени не являются успехом контроля.

Условия: только ограниченный, но немаксимальный floor; неправильное начальное
значение преемника; другие маски второго вызова; циклический возврат выше максимума;
ноль вместо пустоты; возврат floor в промежутке; утрата обязательной маски;
разрешение необязательного бита вне `may`.

Ещё один контроль в отдельной временной копии подменяет доказательство общего
правила заглушкой. Сборка этой копии должна дойти до аудита; аудит обязан обнаружить
недопустимую зависимость. Исходники реального проекта не изменяются.

Разрешённые зависимости — только `propext` и `Quot.sound`. Приёмка требует
`status: accepted`, `lean_checked: true`, всех 22 аудитов, 8 двусторонних контролей
и обнаруженной заглушки. Поле `conditional_floor_contract: true` напоминает о
гипотезе; `json_interpreter_verified: false` сохраняет границу результата.

Workflow `Conditional ceiling composition` заново получает 23 целевых пакета,
строит экспорт двух источников и требует его побайтного совпадения с `Exported.lean`,
который используется в новом доказательстве. Журналы, проверенные исходники,
пакеты и идентификатор точного дерева сохраняются в артефакте CI на 30 дней.
Наличие workflow в Git не означает, что приёмка уже прошла: фактический статус
нужно брать из соответствующего запуска и итогового описания PR.

## Проверки реализации и границы

16 новых Python-тестов проверяют обязательность всех аудитов, отказ при
неизвестных аксиомах и ложных отрицательных контролях, отсутствие Lean,
неперезапись файлов и бюджет. Отдельные конечные сверки: 363 масочных контекста,
9 330 случаев сохранения масок при смене seed с исполнением обоих прежних факторов,
9 330 сравнений числового `compose` и опубликованной JSON-оболочки. Это три
разных популяции, не число новых исходных программ.

В последней сверке нисходящий контракт реализован конечным числовым оракулом.
Она проверяет ветвления и аргументы, но не формализует связь JSON с Lean.
Нынешний JSON-интерпретатор, Python-проверка случаев порядка, фронтенды,
Java-семантика и нисходящий сертификат остаются отдельными обязательствами.
Не заявлены новая Lean-проверка исходного Graal helper, новая знаковая JVM-теорема,
поддержка внешних функций, публикация wordexpr или новая версия PyPI.
