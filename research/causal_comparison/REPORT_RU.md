# PR46 — результат причинного сравнения и решение по следующему блоку

На двух структурно разных source-семействах автоматический выбор вопросов сокращает число native-запросов. **Полный SDK пока дороже простого PR41 на сопоставимых одиночных задачах.** В сериях из 16 целей reuse окупается внутри SDK на обеих семьях и обеих областях ширины; ordinary-контроль с той же леммой ещё дешевле. На локальном фазовом пилоте forcing корректен, но проигрывает прямым контролям.

Следующий основной шаг — уменьшить повторную проверку и упаковку уже установленных оснований. Расширение frontend и общее включение forcing преждевременны. Defaults сохраняются; F1 остаётся незакрытой формальной приёмкой блока A.

## Проверка, применение и память

Fresh verifier не импортирует producers/planner/SMT; positive replay и apply запрещают полное source-исполнение. Signed witnesses перепроверяются конкретной modular IR-семантикой. Historical lower models сохраняют собственные E/E+ и не переносятся по одному хешу. Отдельный полный normal/optimized replay проверяет manifests, все audit proofs, historical obligations, приложения, identities остальных children и пересчитывает отчёт.

Итоговые normal и `python -O` replay каждый прошли: **111 пакетов, 946 historical obligations, 347 применений, 1044 записи полного журнала**. Search imports — 0. Сохранение базы до и после замера совпало. В CI на измеренном коде `efa5466` полный реестр **22 новых + 1010 прежних = 1032 теста** прошёл в обоих режимах на Python 3.10 и 3.12. Полный CI-эксперимент имеет собственные результаты и времена; его статус указан в PR.

Для certified SDK warm apply измерено как 64 повторения заранее заданной последовательности входов. Стоимости build, cold check и apply разделены; результаты приложения сверяются с независимыми ожиданиями. Это не интеграция в hot path компилятора. Tracemalloc peak получен отдельным процессом без PR46 tracer; он включает Python allocations и встроенную инструментализацию, не RSS. Все времена trace/memory probes исключены из трёх timing samples.

## Решение о развитии

Структурные семейства с уменьшением native-вопросов: arithmetic_low_bits, equality_mask.
Случаи с меньшей median полной proof-cost SDK против простого PR41: не обнаружены.
Против более сильного retained: не обнаружены.

**Инженерные критерии PR46 проверяются полным replay и регрессиями; экономический gate не подменяется структурным.** Default остаётся `no_lemmas` для signed и `direct_cell` для phases. Reuse и forcing доступны явно. Эти development-данные не устанавливают конкурентное преимущество готового Semantic Compiler.

Следующий основной шаг — устранить повторную работу с уже проверенными основаниями внутри одного `build`: один immutable контекст source/IR/G/width, проверка новых фактов при расширении, переиспользование проверенных foundations на checkpoints и выпуск direct DAG с учётом цены промежуточного native packet. Внешний cold checker должен по-прежнему независимо восстановить все основания; перенос между разными source/guard/width не допускается без отдельного доказательства. Приёмка — те же зарегистрированные случаи, отсутствие новых расхождений и снижение полной стоимости против простого контроля, а не только числа запросов.

Небольшая формальная линия **F1** остаётся обязательной: soundness typed chronological ground-DAG и импорта checked lemma. Блок A целиком ещё не закрыт формально. Расширение нескольких frontend и универсального forcing откладывается. После исправления стоимости — один ограниченный word-IR/transformer pilot из roadmap D/G; внешний corpus регистрируется отдельно после фиксации этого движка.
