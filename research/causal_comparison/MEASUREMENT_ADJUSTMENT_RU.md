# Поправка к измерению до полного сравнительного прогона

Исходная регистрация `3919c6ccee028cab428c3f185b52a4383d22519c`, protocol hash
`14659d5ec21a31843f8d0a8386ba8b77d0be7e3521784a2a1192c637d3a96fd5`,
остаётся в истории. В ней одновременно включались общий call/return tracer
и `tracemalloc` в одном audit child.

`pr46_01` остановился из-за попытки повторно создать JSON-журнал через
exclusive writer. Исправлена атомарная запись checkpoint; исходные файлы
и stdout/stderr сохранены.

`pr46_02` остановлен во время третьего case, без зафиксированных
сравнительных отказов: общий tracer в сочетании с tracemalloc давал слишком
высокую цену наблюдения за миллионами Python-вызовов. В принятом PR44 уже
видны миллионы calls в сериях 16 целей. Один отдельный стресс-аудит
`batch_mask_all_16/sdk_reuse` с кешированием метаданных также был остановлен.
Обычный build того же запроса завершился: 7.10 s в локальной диагностике,
28479 canonical proof bytes. Это диагностика аудитора, не результат
сравнения маршрутов и не основание исключить длинные серии.

**Поправка v2:** common call audit и memory probe теперь выполняются двумя
разными свежими процессами. Каждый сохраняет identity полного proof/result;
они должны совпасть с тремя временными повторениями. Audit использует tracer
без tracemalloc; memory child — tracemalloc без дополнительного PR46 tracer.
Встроенные guards, profilers и бюджеты принятых backends сохраняются во всех
процессах. Cold checks и нормальный/optimized полный replay обязательны.

Ни один source, target, G, width, case, route, лимит алгоритма или ожидаемый
исход не меняется. Все 32 case hashes сохраняются. Audit/memory/three builds
и четыре cold checks дают **1044 попытки** на 116 выполняемых парах.
Шесть неподдержанных контрактов остаются в исходном знаменателе 122.

Поправка и новый protocol hash публикуются до итогового полного прогона.
Частичные старые данные не смешиваются с итоговой выборкой; лучшие результаты
не выбираются. Их каталоги и причины прерывания остаются development-журналом.
