# Run27: полезность достаточного интерфейса до оплаты его получения LLM

Регистрация: 6 октября 2026, до основного опыта. Линия QKF → AI из чата; её номера независимы от других research profiles репозитория. Run26 остаётся отрицательным для локального CSV SDK; его исходники, критерии и результаты не изменяются.

**Вопрос:** достаточно ли двух точных законов эффектов нового инструмента, чтобы менять многошаговый план, сохранять цель и экономить полную стоимость запросов? Сильный обычный learner получает те же знания через платные различающие пробы или наблюдения в первой настоящей задаче и использует **тот же** исполнитель. Поэтому успех oracle не объявляется преимуществом новой AI-архитектуры.

## Независимый логический домен

Синтетическая служба версий артефактов, без SQLite и файловой устойчивости. Реализации и checker написаны отдельно; checker не импортирует service, planners или generator. Это самостоятельная модель, а не описание реального сервиса и не исправление durability Run26.

API: create, read, fork, snapshot, write, validate, activate. Артефакты имеют неизменяемые идентификаторы версий; handles указывают на mutable cells. Четыре заранее объявленных класса получаются из двух бинарных различий:

* fork создаёт независимую копию текущей версии либо alias к той же cell. snapshot всегда независим.
* PIN activate публикует неизменяемую проверенную версию из token, даже если handle уже изменён. LIVE требует равенства текущей версии handle версии token, иначе возвращает безопасную ошибку без эффекта. Token можно использовать на другом handle той же версии.

Планировщик видит только public callback/results и программу. Идентификаторы зависят от public seed/counter, не от класса. Oracle получает два истинных факта явно. Python wrapper не является защитой от намеренной интроспекции; LLM-эпизодов здесь нет. Checker после исполнения получает скрытый класс и полный журнал для независимой проверки.

Scope интерфейса: qkf.artifact.logical.v1 и один portfolio, внутри которого класс постоянен. Пробы и задачи используют разные fresh services с одинаковым классом. Перенос выводов на произвольный внешний API не разрешён.

## Программы и сравнения

Примитив: создать A, сохранить точную версию A, записать B, проверить B, продвинуть исходный handle до C, **после этого** опубликовать проверенную B. Итог должен сохранять A в backup и C в source. Одного совпадения текста недостаточно: нужна та же версия.

Selection содержит только этот примитив. Transfer содержит его новые композиции: публикация B с последующим откатом к сохранённой A; две последовательные публикации независимых артефактов с сохранением обоих backups/sources. Их нет в диагностических пробах learner. Эти композиции известны авторам стенда и поддержаны общим ручным исполнителем; это ограниченная проверка использования законов в композициях, не автоматическое создание ранее неизвестного алгоритма.

Portfolio sizes: 1,4,12 public programs; 2 splits ×3 размера ×4 класса =24 paired portfolios. Одинаковые public программы/значения/seed для всех классов и arms. Не более одного probe service и один task service на episode. Всего 8 arms ×24 =192 episodes:

| Arm | Доступ к знаниям |
|---|---|
| safe | Нет скрытых законов; snapshots A и B |
| oracle | Бесплатно даны оба правильных факта; потолок полезности, цена получения фактов исключена явно |
| ordinary_fork | Платная различающая проба fork; activation остаётся неизвестной |
| ordinary_full | Совместная платная проба обоих законов |
| ordinary_online | Получает оба факта в первой настоящей задаче; все диагностические запросы и ошибка LIVE оплачены |
| ordinary_best | Выбирает safe/fork/full/online по заранее заданному uniform prior четырёх классов и public числу компонентов; не видит истинный класс |
| oracle_wrong_fork | Одна fork-фактическая посылка заменена противоположной; диагностическая ablation |
| oracle_wrong_activation | Одна activation-посылка заменена противоположной |

Неверные посылки должны нарушать цели только в соответствующей половине классов. Остановленный ошибкой episode сохраняет полный фактический журнал, terminal state, стоимость и явную ошибку; частичный план сохраняется, если исполнитель его вернул. Неожиданная ошибка приобретения знаний тоже сохраняется как отдельная отрицательная запись. Episode не заменяется повтором.

## Полная цена и сильный контроль

Фиксированные **синтетические единицы API-запросов**: create2, read1, fork1, snapshot3, write2, validate3, activate2. Известная операция с ошибкой оплачивается полностью. Initialization каждой задачи, mandatory writes/validate/activate, все пробы и ошибки входят в итог. Это не измерение денег, production latency, CPU или полной стоимости разработки. Запись/audit логов относятся к экспериментальной инфраструктуре; их время не подменяется API-единицами и не используется для performance-вывода. Oracle acquisition и будущие LLM-вызовы не включены в этот потолочный arm.

Fork-only probe: create → fork → write → read, цена6. Full probe делит один write между различениями: create → fork → validate → write → read → activate, цена11.

Online начинает с защищённого snapshot A; дополнительный fork/read при обязательной записи B различает copy/alias. После validate B сохраняет B через fork либо snapshot по уже полученному факту. Обязательная запись C и попытка activate исходного handle различают PIN/LIVE; при LIVE безопасная оплаченная ошибка сопровождается публикацией защищённой B. Обе цели соблюдаются. Только после этих наблюдений остальные компоненты получают оба факта и общий executor. Цена первого компонента по четырём классам17,19,19,21 (среднее19), следующих12,13,14,17 (среднее14). Этот контроль найден независимым review до freeze; он включён до основного опыта. Знания ordinary берутся только из записанных public results.

При одном примитиве Safe=17; Oracle в copy/pin,copy/live,alias/pin,alias/live =12,13,14,17. Это **аналитические ожидания до исполнения**, а не полученные данные. Rollback добавляет одинаковые5, paired_publish содержит два примитива. Uniform-prior затраты на U компонентов: safe17U; fork6+15U; full11+14U; online5+14U, плюс общие rollback charges. ordinary_best выбирает минимум; tie order safe,fork,full,online. Это сильный явный ordinary конкурент, но оптимальность среди всех возможных adaptive policies не доказана. Known four-class hypothesis space — ограничение опыта.

Порог15% — ранее предложенный практический ориентир, теперь зарегистрированный. Показываем все strata; не маскируем провал малого portfolio pooled средним. Дополнительно пересчитываем те же traces при равной цене каждого запроса (1) и при дорогих write/create (write10, create5, остальные основные цены). Это sensitivity фиксированных планов, не новый оптимизированный policy при других ценах.

## Проверка и gates

Source/manifest SHA freeze содержит явный execution_order array. Все192 files, их полные SHA/bytes и policy bindings проверяются отдельно. Fresh cold process независимо воспроизводит каждое действие, IDs, ошибки, стоимость, hashes и весь terminal state; затем проверяет version goals логической модели и порядок фаз. Запрещено принимать producer goal_verified или только финальную publication строку.

Consistency gate требует192 корректных записей,144/144 целей шести основных arms,48 целых ablations с ожидаемым разделением целей (24 goal FAIL). Неверные знания — запланированные отрицательные controls, а не повреждение данных. Pipeline success означает корректный опыт, не победу гипотезы экономии. Экономические gates требуют consistency; при повреждении записей стоимость и экономия не объявляются проверенными.

Interface causal use gate: правильные факты удовлетворяют цели, замены фактов предсказуемо нарушают их, независимый replay проходит. Oracle utility15% gate: oracle экономит ≥15% относительно safe **в каждом transfer stratum** по суммам четырёх равновесных классов. Beyond strong ordinary15% gate: тот же порог против ordinary_best, включая его обучение. Частичное/нулевое преимущество сохраняется в таблице. CSV release BLOCKED при любом исходе Run27.

## Воспроизведение и хранение

Linux/Python3.12, stdlib. Из корня:

```sh
cd research/qkf_ai/run27
python -m unittest test_service27 test_planners27 test_online27 test_runner27 test_check27
cd ../../..
python research/qkf_ai/run27/run27.py --output reproduction/qkf_ai_run27_01
```

Output должен быть новым. --freeze используется только для исходной регистрации, не обхода mismatch. Повторное audit27 сохранённых records — replay, не новые решения/исполнения. GitHub Actions запускает тот же freeze и сохраняет полный небольшой artifact даже при FAIL; код, summaries и полный основной retained corpus планируется сохранить в Git. Дальние выводы после опыта должны отделять достаточность фактов, дешевизну обычного обучения и отсутствие проверки LLM/new architecture.
