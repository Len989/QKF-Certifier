# Явно выбранные словные выражения

Следующий шаг после внешнего эксперимента PR #14. База: `09f1860`.
Это новый исследовательский вход, а не изменение замороженных Java-профилей.
Публикация и фактический CI фиксируются отдельно в PR; наличие workflow само
по себе не является успешной проверкой.

## Что поддержано

Из полного UTF-8 файла выбираются **класс и метод, указанные пользователем**.
Нет проверки на имя `computeLowerBound` или `setOptionalBits`. Поддерживается
один однозначный лексический класс и непосредственно объявленный в нём
`static long method(long argument)`. Имя метода не назначает ему семантику.
Перегрузка с `int` и методы вложенных классов не подменяют выбранный метод.

Тело состоит из присваиваний, инициализированных локальных `long`/`final long`
и одного окончательного `return`. Унарные операции: `+`, `-`, `~`;
бинарные: `+`, `-`, `&`, `|`, `^`; скобки; десятичные литералы `0L`..`2^63-1`.
Все выражения имеют тип long: даже обычный `1` без L пока отвергается.
Отслеживаются прежние значения при присваивании и запрет записи в final.
Вызовы, поля, аннотации выбранного метода, преобразования типов, int,
сдвиги, умножение, ветвления, циклы и побочные эффекты не поддержаны.
Неизвестный токен не отбрасывается. `x--y` не превращается в `x - (-y)`.

Это ограниченный лексический перевод, **не полная проверка компилируемости,
классовых инициализаторов, загрузки класса или разрешения имён Java**.
Остальные методы файла не проверяются. Допускается только безопасная форма
Unicode-экранирования в документационных комментариях OpenJDK; остальные
Unicode escapes и text blocks отклоняются. Исходные байты не нормализуются.

## Два независимо выбираемых требования

Спецификация задаётся отдельно от исходника и сертификата. Пример для
оригинального OpenJDK находится в `lowest.goal.json`:

```json
{
  "schema": "qkf-word-expression-goal-v1",
  "contract": "modular-lsb-word-expressions-v1",
  "entry": {"class": "Long", "method": "lowestOneBit"},
  "target": ["lowest_set_bit"]
}
```

`lowest_set_bit` означает ноль на нулевом входе; иначе ровно один бит в
наименьшей позиции, где вход имеет единицу. Цель **не задана формулой `x & -x`**.
Её независимое наблюдение запоминает, встречалась ли единица на младших местах.

Второй вид цели: `['equals', expression]` (в JSON нужны двойные кавычки).
Выражение цели строится из `['input']`, `['const', n]`, унарных `neg/not/pos`
и бинарных `add/sub/and/or/xor`. Например, `['equals', ['input']]` проверяет
тождественность. Неизвестные предпосылки и операции не принимаются.
Сертификат не выбирает себе входной метод или более слабую цель.

## Семантика и математический аргумент

При ширине w>0 все значения — w-битные слова; арифметика идёт по модулю 2^w.
Это единое математическое поднятие выбранного выражения на все положительные
ширины. При w=64 операции соответствуют результатным битам поддержанного
long-выражения, включая переполнение отрицания минимального long. На иных
ширинах это **не исполнение Java**. Нет нового доказательства Lean.

Из тела строится DAG операций; одинаковые узлы разделяются. При продвижении
от младших разрядов к старшим каждый арифметический узел хранит свой перенос:

`total = a + b + carry`, `a - b + carry` либо `-a + carry`.

Евклидово равенство `total = total % 2 + 2 * (total // 2)` верно и для
отрицательных заимствований. У сложения перенос 0/1, у вычитания и отрицания
-1/0. Константа хранит невыданный двоичный суффикс. Побитовые узлы не хранят
состояния. Индукция по DAG и границе разряда даёт биты точного модульного
выражения; конечные переносы отбрасываются. Не нужно выбирать ширину для
поиска состояний или подставлять персональную таблицу для lowbit.

Производитель находит замкнутый достижимый носитель. Проверяющий заново
разбирает внешний исходник, проверяет каждое происхождение состояния и обе
входные колонки. **Неизменённые** `research.observations.producer/checker`
выводят и проверяют вопросы, вынужденные атомные строки, фактор и разделители.
Их минимальность относится к данному конечному автомату, а не ко всем возможным
доказательным архитектурам.

Затем проверяется замкнутый продукт фактора источника и независимой цели.
Каждый переход обязан выдать требуемый бит. Индукция по любому непустому
входному слову устанавливает требование при всех положительных ширинах.
Контрпример дополнительно проверяется отдельным целочисленным вычислителем
исходного DAG и независимой числовой целью; отказ модели или бюджета не
является контрпримером.

Новые доверенные части: лексический перевод, DAG, правила арифметического
среза и числовой смысл цели. Python-код не формально верифицирован. Поиск
производителя не входит в повторную проверку. SHA связывает точные байты,
но не заменяет проверки обязательств.

## Использование

Из корня репозитория, имея полный оригинальный `Long.java`:

```sh
python -m research.wordexpr.cli prove Long.java --spec research/wordexpr/lowest.goal.json --certificate lowest.proof.json
python -O -m research.wordexpr.cli check Long.java --spec research/wordexpr/lowest.goal.json --certificate lowest.proof.json
```

Путь сертификата при prove должен быть новым. Java, SMT и сеть при check
не нужны. Статусы: certified/0, refuted/1, source_unsupported или
budget_exhausted/2, invalid_certificate/3, input_error/64. Неожиданные исключения
не перехватываются как успешный результат. Для автоматизации нужен точный
статус certified, а не просто существующий JSON-файл.

Ограничения: 2 МБ исходника, 200000 токенов файла, 2048 токенов выбранного
тела, глубина 32, 64 узла DAG, 64 состояния источника, 4096 состояний продукта,
5 МБ входного JSON CLI. Это инженерные бюджеты, не оценки сложности; общего
жёсткого лимита памяти процесса нет. Исчерпание поиска не сохраняет сертификат.

## Эксперимент и знаменатели

```sh
python -m unittest research.wordexpr.test_wordexpr -v
python -O -m unittest research.wordexpr.test_wordexpr -v
python -m research.external.frozen_v1.download_sources reproduction/word_inputs
python -m research.wordexpr.experiment reproduction/word_inputs reproduction/word_proofs
```

Полные оригиналы OpenJDK/Lucene берутся по неизменяемым ревизиям PR #14 и
проверяются по Git blob. Двенадцать ранее изученных методов теперь являются
**набором разработки**, а не новой слепой выборкой. Ожидаемый результат нового
профиля: lowestOneBit проходит, остальные 11 остаются неподдержанными. Только
для подходящего метода запускается соответствующая независимая цель.
Это увеличение поддержки на одну внешнюю функцию, не доказательство всех 12.

Отдельно сохраняются 11 сконструированных случаев: 7 сертификатов и 4
контрпримера. Они не увеличивают внешнее покрытие. Оригинальное тело lowbit
компилируется в явной Java-обёртке и проверяется на прежних 9012 входах,
включая ноль и знаковые границы. Нативное совпадение не заменяет индукцию.
Полные исходники, спецификации, сертификаты, результаты и манифест сохраняются
в каталоге вывода и CI artifacts (30 дней). Архивы беседы для воспроизведения
не нужны. Старый frozen_v1 и все 79 его производственных Python-файлов
проверяются на неизменность; его прежний результат 0/12 не переписывается.

Набор тестов включает 60 случайных выражений с 7560 сравнениями битового
и целочисленного исполнения на ширинах 1..6, а также 50 lowbit-проверок
на ширинах до 4096. Это проверки реализации, не независимые внешние программы.
В дальнейшем нужны расширение грамматики и новая отложенная выборка.

Семантические ориентиры: Java Language Specification, §§3.2–3.5, 15.15.4–5,
15.18.2, 15.22.1 (лексика, отрицание, дополнение, арифметика, битовые операции).
