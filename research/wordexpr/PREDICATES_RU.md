# Булевы наблюдения после чтения слова

Следующий этап после PR №16, база `88a29cd82db445b3a7c0e16f4a63ad16f4adc877`.
Новый маршрут использует прежние арифметические срезы и прежнее ядро вопросов,
вынужденных атомных строк и факторов. Он не добавляет специальную таблицу
под Lucene и не меняет контракты словных результатов из PR №16.

## Вход и независимая цель

Выбор класса/метода и тип аргумента задаются явно. Поддержаны прямые объявления
`static boolean f(int x)` и `static boolean f(long x)`. Все словные значения
в одном методе имеют один тип. Внутри разрешены прежние операции
`+`, `-`, `~`, `&`, `|`, `^`, равенства слов `==`/`!=`, булевы `!`, `&&`, `||`,
булевы константы и типизированные локальные переменные, включая `final`.
Единственный окончательный `return` обязан иметь тип boolean. Порядок
обновления локальных переменных сохраняется через DAG их текущих значений.

Для int разрешены десятичные константы от 0 до `2^31-1` без L; для long —
от 0L до `2^63-1L`. Смешанные типы, неявные преобразования и даже легальное
специальное написание `-2147483648` намеренно не включены в этот профиль.
Булевы `&`/`|`/`^`, равенство булевых значений, числовые сравнения, сдвиги,
вызовы, поля, casts, несколько аргументов, условные словные выражения и циклы
пока отвергаются. Неподдержанный исходник не является ошибочной программой.

Пример для оригинальной функции Lucene:

```json
{
  "schema": "qkf-word-predicate-goal-v1",
  "contract": "modular-lsb-word-predicates-v1",
  "entry": {"class": "BitUtil", "method": "isZeroOrPowerOfTwo"},
  "word_type": "int",
  "target": ["popcount_le", 1]
}
```

`popcount_le(k)` означает не более k установленных битов; `popcount_eq(k)` —
ровно k. Разрешены k=0..3 и логические комбинации `not`, `and`, `or` этих целей.
Это независимое позиционное требование, не равенство с формулой исходника
`(x & (x-1)) == 0`. Произвольные внешние предусловия не принимаются.
Здесь степень двойки относится к **беззнаковому битовому представлению**:
у Java `Integer.MIN_VALUE` ровно один установленный бит, и исходный предикат
возвращает true. Это соответствует комментарию исходного Lucene-метода.

## Почему конечное наблюдение достаточно

Пусть выбранный метод переведён в DAG словных операций и формулу равенств
этих слов. Узлы слов используют неизменённые `wordexpr/semantics.py`:
на каждом разряде `total = bit + 2 * next_carry`, в том числе при заимствовании.
Индукция по DAG и разрядам даёт точные биты модульных значений.

Для каждой пары сравниваемых слов A и B новый остаток D означает:
«на уже прочитанных позициях нашлась различающаяся пара битов».
Начальное значение D=false, шаг — `D' = D or (a != b)`.
По индукции после w разрядов D=false тогда и только тогда, когда A=B
как w-битные слова. Булева формула из этих равенств вычисляется **после
последнего разряда**, а не по первому биту и не по последней паре битов.
В исходной модели переходы имеют неинформативную метку `_`; наблюдаемым
результатом является терминальная метка true/false. Старое ядро QKF уже
поддерживает терминальные вопросы и обязано сохранять их в каждом классе.

Спецификация независимо запоминает C=min(K+1,число прочитанных единиц),
где K — наибольший порог среди атомов требования. Такое отсечение сохраняет
все сравнения `count <= k` и `count == k` при k<=K. На каждом шаге
`C' = min(K+1,C+input_bit)`. Это общий вывод наблюдения для данного языка
пороговых целей; выбор имени исходной функции на него не влияет.

Сертификат содержит происхождение состояний источника, старый QKF-сертификат
его фактора и замкнутый продукт фактора с C. Проверяющий заново разбирает
полный источник и внешнюю спецификацию, сверяет начальные состояния, каждое
происхождение, все обе входные колонки и терминальный результат **после
каждого перехода**. Проверяются в том числе переходы, возвращающие начало.
Тем самым охвачены все непустые слова; начальный пустой вход не используется
как контрпример. Индукция по длине даёт требование для каждой w>0.

Это математический аргумент для указанных правил, **не новая теорема Lean**.
Лексический перевод, арифметические срезы, правила равенства и подсчёта
остаются доверенными Python-компонентами. Независимый replay не запускает
производитель, Java или SMT. Количество классов минимально для данного
конечного автомата в смысле старого QKF-контракта, не среди всех возможных
доказательных представлений.

## Математическая ширина и Java — разные утверждения

Модульная семантика поднимает выражение на любую положительную ширину.
Соответствие выбранным исходным операциям Java относится к w=32 для int
и w=64 для long; другие ширины не являются исполнениями JVM.

Положительный универсальный сертификат охватывает и эту исходную ширину.
Но найденный контрпример на ширине 1 не обязан опровергать Java-метод.
Показательный контроль — `return 2 != 0;` с тождественно истинным требованием:
на математической ширине 1 константа 2 превращается в 0, а на 32 битах — нет.
Отрицательный результат сохраняет точную ширину и отдельно сообщает
`native_width_check`: числовую проверку при исходной ширине, явно помеченную
как IR-вычисление, а не нативное исполнение. Этот контроль не объявляется
ошибкой Java и не удаляется ради процента успешных случаев.

## Эксперимент и воспроизведение

```sh
python -m unittest research.wordexpr.test_predicates -v
python -O -m unittest research.wordexpr.test_predicates -v
python -m research.external.frozen_v1.download_sources reproduction/predicate_inputs_01
python -m research.wordexpr.predicate_experiment reproduction/predicate_inputs_01 reproduction/predicate_results_01
python -O -m research.wordexpr.predicate_cli check reproduction/predicate_results_01/lucene.java --spec research/wordexpr/predicate.goal.json --certificate reproduction/predicate_results_01/lucene.certificate.json
```

Для получения доказательства вместо `check` использовать `prove` и новый
путь сертификата. Коды: certified/0, refuted/1, source_unsupported или
budget_exhausted/2, invalid_certificate/3, input_error/64. Существующие
результаты не перезаписываются. Исключения и тайм-ауты не считаются успехом.
Бюджеты: 64 узла словного DAG, 8 атомов равенства, глубина булевой формулы 32,
128 развёрнутых булевых узлов, 64 состояния источника, 4096 состояний продукта.
Остальные ограничения источника/JSON унаследованы от предыдущего маршрута.

Один **новый** внешний метод — `BitUtil.isZeroOrPowerOfTwo(int)` — выбран в уже
просмотренном файле Lucene 10.3.0, на ревизии
`e2871287e4a378739f0b74081d124e3668347875`, Git blob
`2389e3b0485dbd754593957986c78c8b83573aad`.
Он не входил в прежний набор 12 методов. Поэтому этот эксперимент не меняет
исторические знаменатели 0/12 или 1/12 и не называется слепым holdout.

Четыре состояния реализации дают три класса QKF, три состояния продукта и
шесть переходов. Отдельные сконструированные примеры охватывают семь
положительных и пять отрицательных результатов. Полный неизменённый класс
`BitUtil.java` компилируется вместе с отдельным вызывающим классом; выбранный
метод выполняется на 69 711 различных 32-битных представлениях, включая все
65 536 входов 0..65535, степени двойки, знаковые границы и фиксированные
случайные значения. Сравниваются Java, whole-word DAG, проверенный фактор и
независимый подсчёт единиц. Это не формальная проверка всего класса или всех
2^32 аргументов. Java нужна для этого опыта, но не для replay.

Workflow `Terminal word predicates` проверяет Python 3.10/3.12, Java 17,
новые и прежние тесты, полные исходные Git blobs и побайтное совпадение
артефактов обычного/оптимизированного запуска. Полные 13 сертификатов,
источники с исходными уведомлениями, аргументы и результаты сохраняются в
артефактах CI на 30 дней. Конфигурация workflow сама по себе не свидетельствует
об успешном запуске; точный коммит и фактические результаты фиксируются в PR.

Ни производитель/проверяющий QKF, ни его существующие доказательства, ни
`wordexpr` v1-схемы не изменены. Единственное расширение прежнего исполняемого
файла — параметры типа и результата лексического выбора метода; значения
по умолчанию сохраняют прежний long-to-long вход. Старые сертификаты
проверяются и сравниваются отдельно. Устанавливаемый публичный пакет пока
не получает новый API автоматически.
