# PR40: переносимое запросное finite-ground ядро статьи II

Ядро принимает конечные **ground**-уравнения E и пары запрошенных термов O.
Оно строит хронологическое доказательство равенства или проверяемую конечную
разделяющую модель. Математическая область — последствия данного E; программа,
семантика её операций и параметрические факты не предполагаются доказанными.
Source-адаптеры — следующий PR41, см. `PILOT_PLAN_RU.md` и roadmap v0.4.

## Вход и API

```python
from research.ground_query.producer import prove
from research.ground_query.checker import check

request = {
    'schema': 'qkf-ground-query-input-v1',
    'sorts': ['A'],
    'signature': {
        'a': {'args': [], 'result': 'A'},
        'b': {'args': [], 'result': 'A'},
        'f': {'args': ['A'], 'result': 'A'},
    },
    'nodes': [
        {'op': 'a', 'args': []}, {'op': 'b', 'args': []},
        {'op': 'f', 'args': [0]}, {'op': 'f', 'args': [1]},
    ],
    'equations': [[0, 1]],
    'queries': [[2, 3]],
}
certificate, telemetry = prove(request, mode='entailment')
result = check(request, certificate)
```

Каждый узел ссылается на более ранние аргументы. Сортность проверяется для
каждого применения и равенства. Повторные синтаксические узлы отвергаются;
множество узлов должно в точности равняться Sub(E) ∪ Sub(O). Невстречающиеся
символы сигнатуры и сорта без ground-термов допустимы: модель всё равно имеет
непустой домен каждого сорта и полную интерпретацию каждого символа.

Запросы упорядочены и полностью связаны с сертификатом. По умолчанию конечный
горизонт H=max(h(E),d_O), для пустого входа H=0. `horizon=D` допускает меньший
горизонт, если все запрошенные термы на нём активны.

| Режим / результат | Проверенное значение |
|---|---|
| `entailment`, `equal` | Доказано равенство; `proof_depth` — глубина предъявленного вывода, минимальность не заявляется. |
| `exact_threshold`, `equal` | Вывод на d и разделяющая модель на d−1, если d выше глубины концов; установлен точный первый горизонт. |
| `not_visible` | Модель разделяет запрос на ограниченном D<H; из всего E равенство ещё может следовать. |
| `not_entailed` | Полная модель E разделяет запрос на H; это не универсальное неравенство и не выполнение программы. |

Если точная глубина равна глубине одного из концов, нижний горизонт не содержит
сам запрос: нижняя модель не нужна. Пустой путь доказывает только рефлексивность.
Обычный режим вправе принять неминимальный валидный proof и не навязывает поиск
нижней модели для положительных целей. Текущий producer по-прежнему вычисляет
все снимки активации до выбранного горизонта — ранняя остановка по потребителю
здесь не заявляется.

## Что проверяет самостоятельный checker

Схема `qkf-ground-query-certificate-v1` содержит input hash, режим/горизонт,
события axiom/congruence, модели и ровно один результат для каждого запроса.
Checker не импортирует producer, прототип, solver или closure engine.

У axiom-события проверяются реальные концы указанного входного уравнения.
У congruence-события совпадают символы, все аргументы и их сорта, а каждая
посылка является связным путём из **строго более ранних** событий. Направление
ребра пути можно обращать. Глубина пересчитывается по концам и всем посылкам.
Подмена порядка, пропуск аргумента, завышенное утверждение минимальности и
сохранённый receipt вместо доказательства отвергаются.

Модель задаёт непустые конечные домены и разреженные таблицы с типизированным
default. Это полные операции, в том числе для отсутствующих в DAG применений.
Checker вычисляет значения термов и проверяет **все** уравнения E, активные на
горизонте модели, а затем неравенство запрошенных значений. Проверка только
уравнений, упомянутых в положительном proof, была бы недостаточной.

Хеш фиксирует запрос; истинность обеспечивают правила и модели. Модель нижнего
горизонта не переносится на расширенное E автоматически. Python schema/compiler,
proof-rule checker и model evaluator остаются доверенной частью; новая
Lean-теорема в этом PR не заявляется.

## Переиспользованный алгоритм и представление

Три модуля из `papers/paper_II/prototype` переиспользованы в отдельном namespace.
`prototype/PROVENANCE.json` перечисляет точные source hashes и преобразования:
относительные импорты и детерминированный обход перемещённых членов класса.
Архивные статьи и прототипы не изменены.

Новый `prototype/terms.py` представляет каждый проверенный узел DAG одним
объектом с кешированной глубиной и устойчивой меткой. Уникальность узлов
гарантирует schema checker. Алгоритм не разворачивает DAG в рекурсивные tuple
деревья; иначе цепь f(t,t) имела бы экспоненциальные затраты хеширования/печати.
Извлечение зависимостей proof выполняется итеративно. Сохраняется алгоритм
инкрементальной активации и снимок разбиения на каждом горизонте; новой общей
асимптотики не заявляется.

Границы входа: 20 000 узлов, глубина 128, арность 64, до 200 000 уравнений,
запросов или proof-событий в соответствующем массиве. Plain JSON ограничен
64 MiB, 4 млн структурных элементов и вложенностью 64; float/NaN, циклы,
нестроковые ключи и неоднозначные JSON-объекты отвергаются. Это пределы
представления, не гарантия wall-time или оптимального поиска. Неуспех не
превращается в частичный положительный сертификат.

## Команды

```sh
python -m research.ground_query.cli build request.json certificate.json --mode exact_threshold
python -O -m research.ground_query.cli check request.json certificate.json
python -m unittest research.ground_query.test_query -q
python -O -m unittest research.ground_query.test_query -q
python -m research.ground_query.conformance NEW_DIRECTORY
python -m research.ground_query.replay NEW_DIRECTORY
python -O -m research.ground_query.replay NEW_DIRECTORY
python -m research.ground_query.preserve
```

Выходные файлы создаются эксклюзивно. CLI код 0 означает, что построен/проверен
валидный сертификат; результаты отдельных целей читаются из `goals`.
Это не означает, что все цели равны: `not_entailed` тоже имеет валидную модель.
Код 2 — отклонённый вход/сертификат или ошибка файла. При `check` режим и горизонт
берутся из сертификата. Публичный установленный `qkf` CLI не изменён.

## Приёмка и границы эксперимента

`REGISTRATION.json` фиксирует 203 точных запроса до зарегистрированного полного
conformance-прогона: 8 named-вариантов и 195 каталановских профилей h=1…5
(2, 5, 14, 42, 132). Это development, не новый внешний holdout.

Для каждого каталановского представления запросы покрывают все пары, включая
рефлексивные, полного слоя T^h. По ним точные lambda восстанавливают delta
каждого слоя. Отдельный процесс использует неизменённый `engine.close` статьи II
на **полном** типизированном ограниченном пространстве и сравнивает разбиения
на каждом горизонте. Reference enumeration учитывается отдельно и никогда не
вызывается новым producer/checker.

Имеются строгий congruence/rewrite gap 2/3 с отдельным конечным rewrite-поиском,
равные теории с разной видимостью, typed interface I с N1=5,N2=3, пустые запросы,
сорта без термов, конечное неследование и ограниченная невидимость.

Fresh replay ставит запрет импорта search/prototype/SMT до загрузки checker,
сверяет точную регистрацию и целостность файлов, проверяет каждый proof/model
и заново получает semantic summary и полные каталановские профили. Он не
повторяет reference experiment; соответствующий раздел отчёта остаётся
результатом отдельного conformance-запуска, а не доверенной семантической посылкой.

Runtime записывается только как цена данного conformance. Нет заявления об
ускорении native source inference, automatic observations, действующем мосте
I, синтезе лемм, поддержке Java или формализации нового ядра. Эти этапы описаны
в новом roadmap. Текущий workflow расширяется без нового архивного CI.
