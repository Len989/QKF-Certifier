## Что проверяется

Две source-derived семьи: conjunction масочных импликаций и арифметические
low-bit identities. В обеих требуется нетривиальный общий вывод
`source = negative`, затем серия независимо заданных consumer expressions.
`G = popcount <= 1`; отрицательность на этой области не постоянна.
Отдельные строки для всех положительных ширин и fixed width 8.

Префиксы 1/4/16 начинаются холодными. В 16 целях нет точных повторов запросов,
но это не 16 семантически независимых свойств на `G`: все они должны совпасть
с одним source. Различные expressions и guards фиксированы до запуска,
не выводятся из желаемого ответа planner. Отдельный `exact_repeats_16` содержит
15 настоящих cache hits, доступных каждому маршруту, и не входит в серии A2.

Основной маршрут и прямой контроль получают одну допустимую лемму. Её
нетривиальный исходный вывод не повторяется в следующих consumer proofs:
`via_lemma` проверенно переводит source-обязанность в равенство правой части
леммы новому consumer. Отдельный тест сравнивает реальные congruence events,
а не только наличие леммы в доступном basis.

Изначальные native premises могут вернуться в residual basis, когда новой
цели нужна общая простая identity. Такие возвраты и дополнительные checkpoints
оплачены. Это не разрешает подменить короткий residual proof доказательством
исходника без ссылки на проверенную лемму.

Для `reuse` против `no_lemmas` backend одинаков. **Точки окупаемости по
суммарным research calls не наблюдается до 16 целей ни в одной из четырёх

отдельного ordinary-without-lemmas маршрута в этой регистрации нет.

Один временной выигрыш reuse на parity/fixed8/4 не сохраняется на 16;

По этим колебаниям нельзя выводить универсальный порог или speedup factor.

**Решение A2: ограниченное включение.** Default остаётся `no_lemmas` с общими
native/exact caches. `reuse` и `direct_cache` доступны для явных экспериментов;
нет автоматического применения межцелевых лемм ко всем одиночным запросам.
Рабочий механизм принят, источник накладных расходов измерен. Переход к
автоматической рекомендации требует отдельного подтверждения полной стоимости;
I остаётся выключен согласно A1. Это не перенос результата на иные профили.

реальное использование общей леммы, цепочку лемм и её холодный replay,
ordinary/exact caches и ablation, закрытие каждой независимой цели,
source/IR/guard/width/algebra rebinding, подмену данных с пересчитанными
хешами, потерю основания, self/forward dependencies, удаление `via_lemma`,
ложный residual proof, типы, DAG cycles, повреждение native parity rows,
конкретные guarded witnesses, модели старого `E`, бюджеты, admission полного
source, immutable context и отказ от receipt/pickle.

Кеш принимает только проверенные source-verdicts. Дополнительные тесты
запрещают перенос `unresolved` lower model через exact cache. Это правило
одинаково у всех контролей; повтор отрицательного конечного обязательства
перепроверяется. `distinct_goals` отдельно от `uncached_goal_checks`, поэтому
такой повтор не выдаётся за новую независимую цель.

Полный current реестр: **880 прежних + 68 новых = 948 тестов**.
Все 948 прошли normal Python и `python -O`. Current CI выполняет те же
проверки на Python 3.10/3.12, experiment, оба fresh replay и pre/post preserve.
Итоговый `pr44_02` также прошёл fresh normal и optimized replay: в каждом
проверены 57 packets и 932 checkpoints, импортов поискового кода — 0.
Новых Lean-теорем и изменения installed CLI нет.

Сохранены байты и режимы **2092** файлов принятой базы. Исключения — только

## Журнал исправлений до публикации

`pr44_01` прошёл все зарегистрированные исходы, а fresh normal/optimized
replay подтвердил 57 packets и 854 checkpoints. Ни одного ложного source
вердикта не обнаружено. Затем unit checks уточнили критерий отсутствия
повторного вывода.

Первый неуспешный тест требовал, чтобы вообще ни один native-факт основания
леммы не использовался следующей целью. Это слишком сильное требование:
например, identity `p AND true = p` полезна и следующему target. Тест заменён
проверкой фактического proof graph и нетривиального общего вывода.

Эта более точная проверка обнаружила реальную ошибку учёта в первом варианте:
`later_goals_using_lemma` отмечал доступность леммы, хотя ordinary CC иногда
выбирал старый source-вывод из восстановленных native premises. Первый run
нельзя использовать как доказательство заявленного reuse у обоих backend.
Исправлена сама обязанность: checked transitivity через `via_lemma`, затем
поиск только residual equality. Оба backend получили одинаковую композицию.
Scope, семейства, цели, бюджеты и expected outcomes не менялись.

При review дополнительно устранено нестрогое Python-сравнение `true == 1`
на границе guards/width/scope. Используются точные immutable JSON snapshots.
Непереносимые lower models исключены из exact source-verdict cache; native
failed-question memo и обычные кеши положительных/конкретных результатов
сохранены у всех маршрутов.

Логи `pr44-tests-01.log` и `pr44-tests-02.log` с обоими отказами сохранены.
После исправления composition прошли 63 теста, затем полный реестр 946;
после двух тестов negative-cache — итоговые 948 normal/optimized.
`pr44_02` повторяет тот же зарегистрированный корпус на итоговом коде.
Старый `pr44_01` остаётся архивом development-формата до явного `via_lemma`;
он не подменяет итоговый пакет и не объявляется совместимым с новым checker.

После итогового запуска уточнены только интерпретационные поля `A2.json`:
same-backend ablation отделена от совместной смены backend и включения леммы.
Флаг выигрыша основного маршрута теперь относится только к `reuse` против
`no_lemmas`. Код доказательства, зарегистрированные случаи и измеренные
результаты не менялись; новый временной запуск для выбора более выгодных
чисел не выполнялся.
