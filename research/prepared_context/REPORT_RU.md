## Семантика и доверенная граница

Полный CI выполнил 24 новых и 1053 прежних теста в normal и `-O` на Python 3.10/3.12; signed population — все 27 случаев PR47 × 4 конфигурации, включая refuted, unresolved, unsupported, empty domain и структурный budget. Проверены мутация входного dict после admission, неизменяемость вложенного IR, подмена source/IR/profile/selection/G/width/algebra, stale promotion, forward references, модель старого E и подмена оснований после выдачи capability. Полный horizon сохраняет ground proofs и статистику старых ordinary/query алгоритмов; bounded ordinary отдельно проверен на gap без query fallback.

| Python | Проверенные пакеты | Исторические checkpoints | Проверенные apply | Normal/-O |
| --- | ---: | ---: | ---: | --- |
| 3.10 | 56 | 459 | 20992 | совпали |
| 3.12 | 56 | 459 | 20992 | совпали |

В свежих checker-процессах search imports = 0, положительное full-source execution запрещено; конкретные refutations в регрессионных тестах проверяются прежним verifier. JSON не несёт доверенных receipts. Python capabilities привязаны к одному build и точной presentation/obligation; защита от Python reflection и межверсионный транспорт не заявляются.

Бюджет max_work продолжает считать фактически выполненные research Python calls, включая новый код. Их число уменьшилось, поэтому прежний порог calls и новый порог имеют разное ресурсное поведение. Все исходы сравнивались при прежних достаточных структурных лимитах; в зарегистрированном fact-budget случае оба пути по-прежнему дают resource-budget unresolved. Это не добавление семантического покрытия.

## Длительность CI и публикация результата

Измерения PR48 заняли 28 минут 33 секунды. Полный регрессионный workflow завершился за 26 минут 32 секунды. Основная задержка — [повтор полного PR46/47 benchmark](https://github.com/Len989/QKF-Certifier/actions/runs/35648835573): 2 часа 56 минут 8 секунд, 14 jobs при `max-parallel: 2`. Все завершились успешно. Это длительность всего workflow, включая очередь его matrix jobs.

Этот отчёт и полный числовой журнал опубликованы отдельным Git-срезом с родителем `dac33a16a536db39e6c6ba89ebfffff9f5e9ee37`. Он добавляет только два файла результатов и сохраняет точный проверенный engine. Описание PR48 ссылается на этот срез; принятие кода не требует повторного запуска полного benchmark из-за публикации отчёта. При следующем изменении проекта отчёт можно включить в основную ветку обычным cherry-pick этого коммита.

## Решение

PR48 выполняет подготовку контекста один раз внутри build и сохраняет прежнюю независимую проверку. Результат ограничен зарегистрированными development-примерами. Главные контроли PR47, default и критерий PR52 остаются прежними. Следующий PR49 должен убрать промежуточный пакет и повторную экспортную проверку, сохранив тот же контроль полной стоимости. F1 остаётся открытым.
