# Совместный запрос и фактическая инстанция двух статей

## 1. Какой вопрос задаём

Пусть C — множество слов одной фиксированной ширины, одновременно
удовлетворяющих must/may-маске, знаковому диапазону [l,u] и разрешению
или запрету нуля. Для бита k наблюдаем множество
O_k(C) = {bit_k(x) : x ∈ C}. Возможны четыре значения: ∅, {0}, {1}, {0,1}.
Пустота — самостоятельный ответ, а {0,1} сопровождается двумя настоящими
словами-свидетелями. Отдельная сводка возвращает точные min/max, must/may,
наличие нуля и мощность C. При мощности 1 восстанавливается целое слово.

Все условия относятся к одному x. Проекция каждого ограничения отдельно
с последующим соединением одних только битовых ответов может забыть эту
связь. Отсюда необходимость совместного носителя, а не просто большего
набора независимых признаков.

## 2. Нативный мост к конечным клеткам

Ключ x xor sign_bit превращает знаковый порядок слов в беззнаковый.
Диапазон ключей покрывается выровненными префиксными цилиндрами. В каждом
фиксирован старший префикс, а младшие биты свободны. Пересечение цилиндра
с той же маской снова имеет простой масочный вид или пусто. Если нужно,
удаляется единственная точка, соответствующая нулю.

Нативный проверяющий вычисляет точные местные сводки и проверяет каждый
шаг соединения. Существенны полное покрытие, отсутствие пересечений,
связь с исходными границами, ацикличность и использование всех клеток.
Мощности можно складывать только после проверки непересечения поддержек.
Объединение сохраняет наблюдение O_k: O_k(A∪B)=O_k(A)∪O_k(B).

Производитель использует обычное префиксное разложение интервала. Это
алгоритмическая реализация нативного моста, а не новая теорема о факторе
из статей. Статьи задают требование к наблюдаемой строке и её согласованному
продолжению. Проверка локальной арифметической семантики предъявлена отдельно.
Размер списка клеток ограничен 2w+1; времени по битовой модели и общей
минимальности такого разложения здесь не утверждается.

## 3. Настоящий защищённый носитель из статьи I

Для конечного примера берём A = P({0,1}) с операциями объединения и
пересечения. Имена элементов: empty, zero, one, both. Проверенный совместный
арифметический запрос ширины 4 имеет C={5}; для бита 2 его образ J={1}.
Действие строки задаётся h_J(X)=X∩J. Оно сохраняет обе операции.

Заданы две supplied-клетки:

| Вход строки | Заданный выход |
|---|---|
| zero = {0} | empty = ∅ |
| one = {1} | one = {1} |

Эти входы порождают A: их пересечение даёт empty, объединение — both.
Сохранение операций вынуждает всю строку. Её значения:

| X | h_J(X) | Класс ядра строки |
|---|---|---|
| empty | empty | 0 |
| zero | empty | 0 |
| one | one | 1 |
| both | one | 1 |

Полное h_J предъявлено как допустимое расширение, сохраняющее четыре
различных элемента A. Поэтому центральное отношение не склеивает исходный
носитель: он защищён. Это отличается от ядра самой строки, которое имеет
два класса. Вынужденная область строки равна всему A; строка факторизуется
по своему ядру. Нельзя называть эти два разных отношения одним фактором.

Инстанция строится в ground-семантике статей с операциями положительной
арности. Перечислены конкретные таблицы исходных носителей и условия
сохранения; не добавлены молча глобальные аксиомы дистрибутивной решётки
на весь порождённый носитель.

## 4. Двусторонняя видимость из статьи II

Цель: alpha(joint,both)=one. Для её положительного вывода нужна конструкция
с объединением двух supplied-входов. Исходный прототип статьи II на полной
презентации из 66 уравнений выдаёт вывод из 9 событий с максимальной
глубиной 2. Экспортированный положительный сертификат проверяется по
индексам исходных уравнений и уже установленным конгруэнтным предпосылкам.

Отрицательная сторона — конечная модель из 7 элементов с таблицами
операций и значением по умолчанию. Проверены все 34 уравнения презентации,
активные на горизонте 1, а не только встреченные производителем шаги.
В этой модели цель не равна. Вместе это доказывает точную видимость 2
для данной презентации.

Арифметический ответ J проверяется раньше и служит нативным входом
ground-инстанции. Пример показывает действительное применение результатов
статей к наблюдениям, но не выводит вычисление J целиком из ground-насыщения.
Он также не доказывает, что общий arithmetic query или весь AND имеют
минимальную глубину 2.

Пять файлов оригинального Paper II runtime сохранены без изменений;
`paper_ii_runtime/SOURCE.json` фиксирует их хеши. Поиск используется при
производстве примера, включая оригинальный congruence closure. При replay
сохранённого сертификата модули поиска блокируются. Использование этого
прототипа описывается прямо; оно не выдаётся за новый SMT-алгоритм.

## 5. От наблюдения к исходному `create`

Для масочного носителя M его крайние знаковые значения достижимы. Если
l≤min(M), max(M)≤u и ноль разрешён, дополнительные условия не меняют M.
Символические сертификаты доказывают эти неравенства в реальных ветвях
исходника, проверяют совместимость маски, строки префиксного инварианта
и установку необязательных битов. Нативная лемма о цикле и порядке связывает
это с точными Java-телами и исходным лимитом 3.

Универсальность этой леммы ограничена её предпосылками. Общий конкретный
запрос уже работает при l>min(M), u<max(M), исключении нуля и пустоте;
из этого ещё не следует универсальная корректность всех ветвей исходного
`create` и его стабилизации за 3 прохода. Этот разрыв и является следующим
этапом. Полезный отрицательный ориентир: при запрете нуля явная маска,
которую возвращает Graal, не обязана совпасть с лучшими битами полного
совместного носителя. Пример {-127,1} не позволяет принять такую ложную
промежуточную лемму.
