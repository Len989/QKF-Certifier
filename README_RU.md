# QKF Certifier

[![Test and build](https://github.com/Len989/QKF-Certifier/actions/workflows/ci.yml/badge.svg)](https://github.com/Len989/QKF-Certifier/actions/workflows/ci.yml)

**Самостоятельный инструмент проверки KnownBits-трансформеров с сертификатами
для всех положительных разрядностей.**

Подготовлена версия **0.2.0a1**, исследовательская альфа. Она объединяет
устанавливаемый пакет, последующие эксперименты с наблюдениями и целыми словами,
границы Graal и первый Lean-проект. Третья статья переписана как версия 2.0.

Установленная команда `qkf` по-прежнему завершает покоординатные доказательства
AND, OR и XOR. Более широкие результаты запускаются отдельными командами из
полного репозитория или исследовательского архива:

| Часть проекта | Что уже получается |
|---|---|
| Публичный CLI | AND/OR/XOR для всех положительных разрядностей |
| Исследовательский KnownBits | 11 полных программ из 39; 104 компонента из 411 |
| Верхняя граница Graal | Точный максимум допустимых слов и различение пустоты |
| Нижняя граница Graal | Сохранение общего множества при явном условии на знак |
| Lean 4.33.0 | Форсированные строки, фактор переноса, склейка и числовая теорема о следующем слове |

Для повторения сохранённых доказательств нужны Python 3.12 и Linux/POSIX:

```sh
python tools/replay_research.py --suite all --output reproduction/run_01
```

Каталог результата должен быть новым. Данные проверяются по хешам и
распаковываются; JSON после распаковки занимает около 488 МБ. SMT и Java для
повторной проверки не нужны. Для формальных доказательств, после установки Lean:

```sh
cd research/lean
lake build
```

Теорема о нижней границе требует `lower <= 0` либо запрета отрицательного знака;
граница может быть консервативной. Полный Graal `create` пока не закрыт. Lean
проверяет указанный математический фрагмент и модель ячеек, а не весь Java/Python.
Общее превосходство над SMT по скорости или охвату пока не установлено.

Wheel и обычный sdist содержат устанавливаемый CLI. Исследовательские модули,
статьи и команды выше находятся в полном архиве исходников.

## Быстрый запуск

Python 3.10 или новее, команды из корня распакованного репозитория:

```sh
python -m venv .venv
# Linux / macOS:
. .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install .
qkf verify examples/ntmy/xor.mlir --target xor --helper meet=examples/ntmy/meet.mlir --certificate xor-proof.json
qkf check examples/ntmy/xor.mlir --target xor --helper meet=examples/ntmy/meet.mlir --certificate xor-proof.json
```

Ожидается `certified`: корректность для всех положительных разрядностей при
заданной семантике операций, а также `optimal=true`. Сертификат связан с содержимым
основного исходника и helper. Изменение файла требует нового доказательства.

## Команды

| Команда | Что делает |
|---|---|
| `verify` | Строит и проверяет доказательство для явно заданного AND/OR/XOR |
| `check` | Воспроизводит готовое доказательство без поиска упрощений |
| `normalize` | Доказывает только равенство исходника и нормальной формы |
| `inspect` | Показывает оставшиеся операции и точную семантическую сигнатуру, когда она существует |
| `batch` | Проверяет несколько программ из JSON-манифеста |

`--json` выводит результат для автоматизации. Образец пакетного запуска:

```sh
qkf batch examples/batch.json --json
```

Коды завершения: 0 — `certified` или успешная операция нормализации; 1 —
`unsound`; 2 — нужна другая проверка; 3 — неверный сертификат; 64 — ошибка входа;
70 — непредвиденная ошибка реализации. Для принятия трансформера проверяйте
именно `status == "certified"`. Статус `normalized` не доказывает soundness.

## Что доказывает инструмент

Проверяющий код разбирает типизированные SSA-операции и реальные return, раскрывает
вызовы по переданным определениям, проверяет локальные преобразования и девять
однобитовых случаев. После доказуемого сведения к покоординатным операциям результат
распространяется на любую положительную разрядность. Результат условен относительно
явной семантики: непустые входные KnownBits, модульная арифметика, стандартные
счетчики битов и тотальные операции над словами.

Сам Python-код пока не формализован в Lean/Coq. Проверяющий и генератор используют
общие реализации локальных правил, но checker не запускает поиск нормализации.
Корректность отдельного LLVM/MLIR/SMT lowering этот пакет автоматически не доказывает.

В исследовательском предшественнике проверены 680 мутаций, 22 140 входных пар
полным перебором и 3150 случайных пар. В том покоординатном профиле на корпусе из 39 программ полностью
закрыты три. Последующий исследовательский профиль закрывает 11/39; его интерфейс
проверки шире и запускается отдельно. Это не универсальная замена SMT и не доказанное ускорение всего
NiceToMeetYou; точная область и ограничения описаны в [SEMANTICS.md](docs/SEMANTICS.md).

## Проверки и выпуск

- Устанавливаемый Python-пакет и стабильные для данного формата команды.
- Строго проверяемая JSON-схема и отказ от устаревших сертификатов.
- Примеры, тесты математического поведения, CLI и некорректных входных данных.
- GitHub Actions, сборка wheel/sdist, документация разработки и релизов.
- MIT LICENSE, авторство Leonid Shcherbakov, сведения о происхождении примеров.
