# PR50 / F1a: soundness положительного ground-ядра

Самостоятельный пакет **Lean 4.33.0 / Std**, без Mathlib и без миграции
исторических Lean-проектов. Реализован вычислимый checker и доказана его
корректность для положительного decoded typed ground-DAG.

Это формальная поставка PR50 из `docs/QKF_ROADMAP_v0.5_RU.md`.
**F1a завершена; F1 в целом остаётся открытой до PR51.**

## Что доказано

`QKFGround.accepted_goal_values` утверждает: если `check c cert = true`,
то для любой многосортной интерпретации сигнатуры, удовлетворяющей всем
объявленным ground-равенствам E, каждый принятый запрос имеет два конца
одного типа и оба конца обозначают одно и то же значение этого типа.

`QKFGround.check_sound` доказывает более общее утверждение для произвольной
тотальной алгебры. `typed_check_sound` применяет его к многосортной семантике.
`eval_typed` исключает ложную трактовку результата как равенства двух ошибок
вычисления: хорошо типизированный терм действительно получает значение
нужного carrier. Отдельные сорта могут быть пустыми; фиктивный default-элемент
для них не вводится. Типизированная операция получает список значений и
доказательство точного соответствия его типов объявленным аргументам.

`checkRaw_sound` начинает с массива DAG-узлов: **Lean сам** проверяет ссылки
на ранее объявленные узлы, сигнатуру, арности и типы и только затем проверяет
события. Это теорема об объекте `Request`, а не о JSON-байтах Python.

В доказательстве последовательно используются:

1. `walk_sound` / `path_sound`: рефлексивность, проход по равенству в обе стороны
   и композиция пути сохраняют равенство значений.
2. `arguments_sound`: проверены все аргументы конгруэнции, без усечения списка.
3. `event_sound`: событие ссылается на фактическую аксиому E либо следует по
   конгруэнции из уже проверенных путей аргументов.
4. `events_sound`: каждый новый факт корректен; ссылки доступны только в
   предшествующем префиксе. Проверяются и неиспользованные события.
5. `goals_sound` / `check_sound`: проверены все положительные цели в их порядке.

Глубины термов и путей вычисляются заново; заявленные event/goal depths должны
точно совпадать с ними и не превышать horizon. Проверка активности не означает
доказательство минимальности horizon. В `flattened_nonminimal` намеренно
сохранено корректное доказательство с неминимальной глубиной.

## Соответствие действующему формату

Исходный формат: `research/ground_query/schema.py` и `checker.py`, принятые
в commit `55942faaeb253f19b849e9a52ea99cfd4b240a77`. Эти файлы не изменены.

| Поле / действие Python | Объект / действие Lean | Граница |
| --- | --- | --- |
| Имена sorts и symbols | Индексы `Nat`, `Signature` | Нумерация проверяется тестами adapter; теоремы о Python-трансляторе нет. |
| `nodes: op,args` | `Node`, `decodeNodes` | Lean проверяет предыдущие ссылки, наличие head, арность, типы. |
| `equations` | `Context.equations` | Переносится ровно исходное E; выводы не превращаются в новые аксиомы. |
| `rule: axiom`, `equation` | `Rule.axiom`, `eventCost` | Точный индекс и оба endpoint, включая обратную ориентацию. |
| `rule: congruence`, `premises` | `Rule.congruence`, `arguments` | Один head, полная арность и отдельный путь для каждого аргумента. |
| Индексы событий в path | `walk` по принятому префиксу | Будущая ссылка, self-reference и разрыв пути отвергаются. |
| `depth`, `horizon` | `Term.depth`, `path`, `event`, `goals` | Пересчёт фактической глубины и ограничение активности. |
| `equal` goals | `Context.queries`, `Goal` | Все выбранные положительные цели, точные endpoints и порядок. |
| `models`, отрицательные статусы | Не входят в утверждение PR50 | Полный исходный сертификат проверяет прежний Python checker. |
| `exact_threshold` | Экспортируется только положительное следствие | Минимальность и нижние модели не формализованы этим PR. |
| Digest, JSON, бюджеты, уникальность/достижимость nodes | Прежний Python parser + adapter | Общая теорема эквивалентности двух языков приёмки не заявляется. |

`export.py` сначала проверяет **полный** исходный сертификат старым независимым
checker, затем выпускает Lean-данные. Экспорт не импортирует producer.
Имена из JSON не вставляются в Lean-код: экспортируются числовые индексы.

Для смешанного сертификата явно фиксируются `positive_query_indices` и
`excluded_query_indices`. Например, `shared_typed` содержит 36 исходных целей:
23 положительных экспортируются, 13 отрицательных остаются за границей Lean-
утверждения. Все исходные E, узлы и события сохраняются. Это положительная
проекция, а не доказательство всех статусов исходного сертификата.

## Проверяемые данные

`fixtures.py` воспроизводит сертификаты действующим ground producer;
`FIXTURES.json` закрепляет байты запросов, сертификатов, decoded-данных и
сгенерированного `Examples.lean`. Экспорт можно повторить и сравнить побайтно.

| DAG | Узлы | События | Положительные цели |
| --- | ---: | ---: | ---: |
| gap | 7 | 3 | 1 |
| flattened_nonminimal | 7 | 3 | 1 |
| shared_typed | 57 | 15 | 23 |
| typed_binary | 6 | 3 | 2 |
| reflexive | 1 | 0 | 1 |
| reverse_axioms | 7 | 3 | 1 |
| active_prefix | 6 | 1 | 1 |
| empty | 0 | 0 | 0 |
| transitive_chain | 4 | 3 | 2 |

Всего **9 DAG, 32 положительные цели и 28 отрицательных DAG**. Для каждого
сгенерирована теорема о результате checker, проверяемая через `decide +kernel`.
Нативный вычислитель не используется для выдачи доказательства.

23 повреждённых JSON-пары независимо отвергают Python и Lean. Ещё 5 контролей
воздействуют непосредственно на decoded-объект: неизвестный числовой head,
пропущенная/лишняя цель, пустое объявление сортов, сорт вне объявления.

Контроли включают неверные sort/head/arity, ссылки узла на себя/будущий узел,
неверный индекс аксиомы, подмену её endpoints, пропущенный/лишний аргумент
конгруэнции, self/forward event, разорванный путь, неверную глубину, неактивное
событие и ложное неиспользованное событие. Дополнительно CI проверяет отказ
при попытке объявить повреждённый экспорт принятым, а также работу защиты
от proof-hole и дополнительной недоказанной аксиомы.

`Audit.lean` содержит обязательные `#guard_msgs` для 13 общих теорем. Точный
допустимый набор зависимостей — стандартные `propext` и `Quot.sound`.
Новых аксиом soundness, `sorry`, `admit`, `native_decide`, `unsafe` в принятом
Lean-коде нет. CI отдельно собирает зависимости всех **50 деклараций**:
13 общих теорем и 37 результатов приёмки/отказа.

## Повторение

Для формальной проверки достаточно указанной версии Lean / Lake:

```bash
cd formal/ground
lake build
```

Из корня репозитория, для полного воспроизведения с Python:

```bash
python -m formal.ground.fixtures --check
python -m formal.ground.check_ci reproduction/lean_ground --require-clean
```

Второй путь требует чистого git checkout и доступного `lake`. Для рабочего
нефиксированного дерева можно опустить `--require-clean`; такой результат
будет явно помечен `source_dirty`, и не заменяет проверку опубликованного commit.
Runner выполняет чистую сборку, проверку исходных байтов, axiom audit,
отрицательные integrity-контроли и 17 Python-тестов в normal / `-O`.
Результат содержит точные revision/tree, hashes, команды, логи и архив пакета.

Пример отдельного экспорта, из корня репозитория:

```bash
python -m formal.ground.export formal/ground/evidence/gap.request.json \
  formal/ground/evidence/gap.certificate.json reproduction/gap.lean --name gap
cd formal/ground
lake env lean ../../reproduction/gap.lean
```
