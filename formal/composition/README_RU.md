# PR51 / F1b — проверенная композиция лемм

Пакет доказывает в Lean 4.33.0 корректность последовательного импорта
типизированных равенств и вывода новых потребительских целей из исходных
предпосылок. Он использует неизменённое ground-ядро PR50 через локальную
зависимость `../ground`; установленных runtime, SDK defaults и форматов
пользовательских сертификатов этот PR не меняет.

Регистрация: `03a80bd699c3383a8cde988518f37d9e00d173d4`.
Принятая база: `bee1a2ad64668d86054fa91ab4d23bd399bc4789`.
[Исходный контракт](REGISTRATION.json) сохранён без изменений.

## Что доказано

Пусть `E` — явно перечисленные native-предпосылки, `P` — декодированный пакет.
Если `check P = true`, то в каждой алгебре, удовлетворяющей `E`:

1. Каждый импортированный результат истинен, включая леммы, не использованные
   последним потребителем.
2. Каждое потребительское равенство истинно.
3. В типизированной интерпретации оба конца потребительского равенства имеют
   одно и то же **реальное значение** в общей области значений. Это не равенство
   двух результатов неудачного вычисления.
4. Добавление проверенных равенств к `E` не меняет множество моделей `E`:
   `Models (E ++ checked) ↔ Models E`.

Теоремы действуют для произвольных конечных списков записей, сигнатур и
типизированных моделей. Проверка примеров иллюстрирует связь с форматами;
общая корректность не выводится из числа примеров.

## Проверяемый объект

`Packet` содержит сигнатуру, исходные предпосылки, хронологический список
`Entry` и независимые `Consumer` с точными endpoints.

- `native i` вводит только предпосылку `E[i]`, проверяя типы её концов.
- `derived d` содержит полный ground request/certificate, список индексов
  ранее принятых равенств, необязательную ссылку `via`, полную цель и индекс
  её residual-запроса.
- Порядок и endpoints всех ground-аксиом должны точно совпадать с выбранными
  ранее принятыми равенствами. Сигнатура и количество сортов должны совпадать
  с сигнатурой пакета. Ground-DAG декодирует и проверяет Lean-ядро PR50.
- Для `via` ранее доказано `a = b`; ground-сертификат должен доказывать
  **именно** `b = c`. Полное `a = c` получается транзитивностью. Итог леммы
  не становится новой непроверенной аксиомой.
- `Consumer` указывает на ранее принятое равенство и повторяет точные
  endpoints. Подмена цели, forward reference и self-support не принимаются.

Неиспользованные ground-события не выкидываются экспортом. Дополнительные
рефлексивные запросы direct-формата, сохраняющие необходимые термы, остаются
в request/certificate и проверяются PR50. Минимальность графа не заявляется.

## Карта утверждений и доверия

| Утверждение | Lean theorem | Формат / отображение | Оставшаяся граница |
| --- | --- | --- | --- |
| Положительный ground-DAG следует из своих уравнений | `QKFGround.check_sound` | PR50 `Request` / `Certificate`; все события сохранены | JSON и числовое отображение имён |
| Импорт использует только доказанный префикс | `select_sound`, `entry_sound`, `replay_sound` | E/E+ и direct dependencies → хронологические `Entry` | Source epoch и scope проверяет Python-адаптер |
| `via_lemma` доказывает полную цель | `residual_sound`, `derive_sound` | Точная левая граница, residual и ссылка на предыдущий результат | Соответствие символического терма исходнику |
| Все импортированные равенства следуют из исходных native-предпосылок | `all_admitted_sound` | Весь принятый список, включая неиспользованные леммы | Истинность native source-rules остаётся предпосылкой |
| E → E+ сохраняет модели | `conservative_extension` | `E ++ checked` | Та же исходная семантика native-предпосылок |
| Потребительская цель следует из E | `check_sound` | Точная ссылка и endpoints потребителя | Связь decoded claim с независимым source-запросом |
| Типизированные endpoints имеют одинаковое реальное значение | `accepted_consumer_values` | Одна общая сигнатура, PR50 `Interpretation` | Конкретная интерпретация source-операций не формализована этим PR |

Экспорт не утверждает корректность Python JSON parser, name mapping,
frontend или native source-rules как Lean-теорему. Каждый native факт остаётся
отдельной предпосылкой с исходным evidence, scope и identity в `binding`.
Их проверяет прежний независимый Python-checker, но этот код сам по себе
не превращается в доказанную Lean-семантику source.

Проверки чужого source/G/width, точного cached request и SDK interface относятся
к границе адаптера. Хеш фиксирует идентичность, а не доказывает семантическое
соответствие. Отрицательные результаты, lower models, минимальный horizon,
полнота поиска, forcing, whole-transformer soundness и interface→runtime
остаются за пределами F1.

## Реальные сертификаты и воспроизведение

В [inputs](inputs) зафиксированы 12 положительных входов:

- Четыре сохранённых ground-примера PR50, включая разные сорта и обращённые
  аксиомы; все положительные цели сохраняются.
- Четыре E/E+ пакета: цепочка из двух импортируемых лемм с `via`, fixed-width
  parity, exact repeats и контроль без лемм.
- Четыре **исходных** SDK-пакета PR49 из матрицы
  `ordinary/query × no_lemmas/reuse` для `batch_mask_all_4`.

PR49 engine: `0be531350f1e062b04a26fd51915e443765026d5`.
Источник: [CI run 35670602199](https://github.com/Len989/QKF-Certifier/actions/runs/35670602199),
artifact `10671870725`, `emitted-mask-py3.12`.
SHA-256 архива:
`74a29fa33a5d819df4f9df712decf01e3b2745022a6d326b2a4b5f6821b35c29`.
Проверены manifest и delivery identities; `origin` каждого входа сохраняет
хеши конкретного member, case, delivery и packet. Эти файлы используются
для проверки формата, без новых экономических измерений.

`freeze_inputs.py` — отдельный инструмент первоначальной фиксации: ему нужен
оригинальный ZIP, и он явно вызывает прежние producers для E/E+ примеров.
Обычная регенерация и независимая проверка читают сохранённые входы, не
импортируют producers/planners/SMT и ничего не скачивают.

```bash
# Из корня репозитория; Lean 4.33.0 / Std.
python -m formal.composition.fixtures --check
python -m unittest formal.composition.test_export
python -O -m unittest formal.composition.test_export
lake -d formal/composition build
python -m formal.composition.check_ci reproduction/lean_composition --require-clean

# Экспорт одного сохранённого входа.
python -m formal.composition.export formal/composition/inputs/lemma_chain.json \
  reproduction/lemma_chain.lean --name lemma_chain
lake -d formal/composition env lean ../../reproduction/lemma_chain.lean
```

`check_ci` делает чистую сборку PR50 и PR51, повторяет экспорт побайтно,
аудирует все 12 общих теорем и 29 результатов примеров, проверяет отказ при
подмене Lean-export и работу защит от proof hole / дополнительной аксиомы.
Допускаются только стандартные `propext` и `Quot.sound`; точные зависимости
общих теорем закреплены обязательным `CompositionAudit`.

17 отрицательных Lean-пакетов проверяются через `decide +kernel`: будущая
посылка, self-support, отсутствующее основание, неверные endpoints и
сигнатура, повреждённые ground-события, чужая цель, будущий/self `via`, потеря
`via` и ложный residual. Отдельные 28 Python-тестов проверяют привязку к
реальным форматам, в том числе мутации с пересчитанными identities.

Принятые файлы PR50 сохраняются побайтно и по режимам. Единственное изменение
в принятой базе — дополнение `research/regression/SUITES.json`: 1130 прежних
тестов остаются в `prior`, 28 новых выполняются отдельно. Новый formal CI
собирает pinned-пакет и сохраняет исходники и результаты; прежние workflows
и исторические timing-протоколы не редактируются.
