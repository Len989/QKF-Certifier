# PR51 — soundness импорта лемм и привязка сертификатов

PR51 закрывает F1b для декодированного типизированного исчисления: каждая
импортированная лемма и конечная потребительская цель следуют из исходных
native-предпосылок. Вместе с принятой F1a/PR50 это закрывает формальную задачу
F1 в границах roadmap v0.5.

## Результат доказательства

В Lean 4.33.0 / Std проверены 12 общих теорем. Хронологический префикс
разрешает только уже доказанные равенства; ground-аксиомы точно сопоставлены
с этими посылками. Для `via_lemma` проверяется исходный endpoint, доказывается
остаточная цель, затем применяется транзитивность. Полная цель леммы не
подменяется непроверенной аксиомой.

`replay_sound` и `all_admitted_sound` доказывают корректность всех принятых
лемм при исходных предпосылках. `conservative_extension` устанавливает
`Models(E ++ checked) ↔ Models(E)`. `check_sound` связывает итог с точным
потребительским равенством. `accepted_consumer_values` доказывает совпадение
реальных значений обоих концов в общей типизированной области.

Формальное ядро PR50 импортируется без изменений. Отдельный пакет содержит
воспроизводимые адаптеры ground / E/E+ / direct / SDK-direct; все ground
события и дополнительные рефлексивные запросы сохраняются.

## Сохранность и границы

Сохранены **2343 принятых файла PR50**, включая формальное ядро, runtime,
исторические протоколы, результаты и workflows. Из принятой базы изменён
только additive registry: 1130 прежних тестов остаются в `prior`, 28 новых
зарегистрированы отдельно. Добавлен один отдельный formal workflow.
Существующие схемы, defaults и алгоритмы поиска не менялись.

F1 не доказывает истинность native source-rules, корректность JSON parser,
перевода source в symbolic/числовые термы, frontend, interface→runtime,
lower models, минимального horizon или цельного трансформера. Native-факты
остаются явно названными предпосылками, проверяемыми существующим Python
кодом. Проверки чужих source/G/width на adapter-границе не объявляются
общей Lean-теоремой о source-семантике.
