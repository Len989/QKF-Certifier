КАК СВЯЗАТЬ GITHUB СО СТАТЬЁЙ III

Пакет ничего не меняет в опубликованном репозитории автоматически.

После размещения статьи на Zenodo:
1. В CITATION.cff внутри блока preferred-citation добавьте строку
     doi: "РЕАЛЬНЫЙ_DOI_ВЕРСИИ_СТАТЬИ"
   и удалите последнее предложение notes о добавлении DOI.
   Это DOI вида 10.5281/zenodo...., без https://doi.org/.
   Верхний блок остаётся описанием программы. Не ставьте бумажный DOI в него.
2. В README_CITATION_BLOCK.md сделайте название статьи ссылкой на её DOI.
   Вставьте этот блок в README.md репозитория; не заменяйте весь README.
3. В PAPER.md добавьте реальные version DOI и concept DOI.
4. В paper-version.json замените два null в paper на соответствующие DOI.

Куда загружать через сайт GitHub:
  этот файл пакета          путь в репозитории
  CITATION.cff              CITATION.cff  (заменить существующий)
  PAPER.md                  docs/PAPER.md
  paper-version.json        docs/paper-version.json
  README_CITATION_BLOCK.md   только содержимое добавить в README.md

Папки через .gitkeep создавать не требуется: при Create new file можно сразу
ввести полный путь docs/PAPER.md. Имя CITATION.cff обозначает файл.

Ссылка About/Website в репозитории может вести на DOI статьи III.
Общая ссылка в README — на concept DOI; точная цитата версии — на version DOI.
Если все три статьи размещаются файлами одной записи Zenodo, DOI у записи
общий: в цитате обязательно сохранить название III и её версию, а в описании
записи прямо обозначить III как основной текст о программе.

Commit в манифесте — проверенный программный релиз, а не будущий commit,
который добавит эти документы. Не заменяйте его текущим HEAD автоматически.
