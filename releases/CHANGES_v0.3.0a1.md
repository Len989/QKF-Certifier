# QKF-Certifier 0.3.0a1 — complete changes

Prepared 2026-09-22 from the public merged history through PR #51. Release title: **QKF Certifier 0.3.0a1 — inferred observations, checked summaries and compositional proof kernels**.

## Release boundary and version

The previous published prerelease is [v0.2.0a1](https://github.com/Len989/QKF-Certifier/releases/tag/v0.2.0a1), targeting `708a4211b10e955f0eb8673f314d65fec08d74b5`. The accepted research baseline is the PR #51 merge, `eca90f9252da4480d77c1f8cb4b7062470c57b89`. PR #1 prepared the previous release and is not counted again. This update contains **47 merged follow-up PRs: #2–#51, excluding unmerged #6, #7 and #10**. Ideas adapted from an unmerged branch are attributed in the accepted PR where they entered the repository; the unmerged PR itself is not release content.

Version **0.3.0a1** remains a research alpha: the broader source profiles and summary SDK remain repository APIs, their source grammar and target language are restricted, and whole-transformer integration remains unfinished. The tracked `src/` and `pyproject.toml` contents at the PR #51 baseline have no changes from v0.2.0a1. The release kit applies a separate version/metadata update and preserves the implementation.

The installed coordinatewise `qkf` CLI retains its existing public API, AND/OR/XOR target scope, runtime semantics and `qkf-rewrite-v3` certificates. The full research archive is the deliverable for the new modules and Lean projects; the application wheel must not be described as containing all research functionality.

## Release overview

QKF now connects source-derived observations, independent consumer goals and portable checked summaries through several independently replayable research paths. New work covers automatic selection of sufficient observation interfaces, signed terminal predicates, guarded residual coverage, native source facts, typed ground-query certificates, goal-directed questions, chronological cross-goal lemmas and an applicable-summary SDK. The SDK can check a portable proof and then execute its sufficient finite action without executing the original source program.

Two new Lean 4.33.0 / Std packages establish soundness of the decoded typed positive ground calculus and chronological lemma composition. They prove that accepted consumer equalities hold as actual typed values under the explicitly supplied native assumptions. Source parsing, native-rule validity and the correspondence between decoded objects and executable source remain separate implementation boundaries.

The release also includes preregistered external applicability studies, controlled development comparisons and complete lifecycle measurements. QKF's own **ordinary congruence-closure route wrapped in the same SDK** is the strongest measured simple control in the registered PR47–49 comparisons. Its success is a result within QKF; it does not indicate that an external tool replaces the project. The measurements identify where more elaborate query, forcing or lemma mechanisms add cost and where the checked delivery interface already works.

## Grouped changes

### 1. Independent source-to-target proofs and exact word contracts — PR #3–#20

- Source-derived descending and ascending factors replace prescribed phase tables in the supported mathematical regions. Residual offsets, Boolean registers, cut contexts, atomic rows and separating continuations are obtained from admitted source structure. Source-model equivalence is recorded separately from an independently supplied program property.
- Independent maximum/bound and cyclic-successor/membership specifications produce either checked universal certificates or checked concrete counterexamples. The original and irrelevant-register ascending regions have 8-state / 48-transition successor certificates in the original Python profile. The later exported Lean representation has an explicit initialization state and 9 joint states / 54 transitions; these are different representations, not contradictory counts.
- A common research interface and versioned proof envelopes bind source bytes, the external goal, the chosen profile, unchanged inner proofs and the recomputed result. Certification, refutation, exhaustion, unsupported source, malformed proof and input error remain distinct outcomes. Replay runs independently of producer search, SMT and Java.
- Typed word formulas and derived target observations generalize the fixed goals. Source-bound export to the accepted Lean target package is checked cell by cell. The 23-case typed integration population retains 14 positive certificates and 9 checked refutations; it does not represent 23 distinct upstream algorithms.
- Exact OpenJDK `CodeUtil.mask` recognition supports original upstream source bundles. Two pinned Graal revisions retain distinct full-file identities but the same selected algorithms; their successful transfer is revision/source integration evidence rather than expanded algorithm coverage.
- Checked masked-ceiling composition connects an exact floor and exact cyclic successor, with `Value(0)` explicitly distinct from `Empty`. The Python composition profile accepts a restricted typed JSON wrapper. Lean separately proves exact numerical masked successor and conditional floor–successor ceiling composition on legal bit-list carriers; the descending floor contract remains an explicit hypothesis in the conditional theorem.
- Selected unary word expressions and terminal Boolean predicates add source-bound lowest-set-bit and bounded-popcount proofs. Later signed predicates handle positivity/negativity tests against zero. Mathematical widths extend the declared modular profile; a small-width refutation is not automatically a Java int/long counterexample.
- A source-bound Graal `IntegerStamp.create` capsule derives helper premises from the selected caller, preserves denotation and tagged emptiness, obtains exact signed extrema and checks the three-pass stabilization contract in the declared fixed source semantics. Lean proves sign-bucket order, endpoint-prefix refinement, emptiness, extremum tightening, nonwrap premises and conditional stabilization rules. Lean does not parse Java or prove that the source establishes its abstract `Normal` predicate after two changing passes.

### 2. Observation inference, signed execution and guarded coverage — PR #21–#37

- Counterexample-guided observation selection begins with no selected questions and refines a sufficient interface using a finite source-derived candidate library. V2 adds coordinate cuts, equalities and pairwise relations and checks the successor target directly on the inferred quotient. V3 adds bounded continuation observations for signed predicates. These are restricted inference mechanisms, not synthesis in an unrestricted observation language.
- A standalone source-to-IR-to-residual-model bridge gives an explicitly checked positive-width completion model. Backward observation closure derives a finite factor and explanations. An immutable row runtime reuses the checked atomic action. Independently supplied signed targets then run through that row action and receive their own proof obligations.
- Typed source reduction and exact live-dependency slicing happen before residual-carrier expansion. Guarded residual coverage moves the same principle into derivatives and integrates the resulting interface with independent targets. Constructed cases previously above the 64-state limit can complete without raising that limit: `tautology_31` uses 2 covered states; `delayed_31` uses 34; equality to 2^61 reaches 64. The limits and finite local rewrite/guard families remain explicit.
- A separate concrete-witness route checks a finite final-width source/goal mismatch without constructing a complete factor. Failure to find a short witness is `not_refuted` or exhaustion, never correctness. Optional fallback keeps its original profile and complete cost.
- Reusable checked contexts avoid repeated source reconstruction for several independent targets. Portable proofs still carry their full foundations; process-local checked state does not become a trusted serialized receipt.
- Compact dependency DAGs share identical proof data across goals and derive separating explanations on demand. This reduces portable duplication and repeated checking. The original compact path still constructs legacy proofs before packing, and its decoder reconstructs bounded JSON; it is not a zero-copy or source-discovery-memory result.
- Current-tree regressions are separated from explicitly pinned historical workflows. Frozen engines, protocols and old results retain their original identities.

Primary guides: [inference](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/inference/README_RU.md), [signed targets](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/signed_targets/README_RU.md), [guarded coverage](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/signed_coverage/README_RU.md), [checked contexts](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/signed_context/README_RU.md), [compact dependencies](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/signed_compact/README_RU.md).

### 3. Forced rows, ground queries, native facts and applicable summaries — PR #38–#45

- A standalone certifying implementation of Paper I's finite typed pure-row fragment checks forced carrier quotients, row geometry, ambient kernel saturation, forced domains and external classes. Chosen total completions have a separate checker and are not promoted to forced values. The development population contains 5,264 presentations.
- Paper II's typed ground-query core represents shared input subterms as a DAG, activates them by depth and checks chronological axiom/congruence proofs. Positive entailment, exact thresholds with lower models, bounded nonvisibility and nonconsequence of the full supplied presentation remain distinct. Conformance includes 203 cases, all 195 Catalan profiles for horizons 1–5, 419,488 goals and 1,047,311 pair/horizon comparisons against the retained reference.
- Native source facts bind every ground premise to admitted source/IR, explicit guard G and all-positive or fixed modular width. Consumers supply their own target. A finite-theory separator is not a source-program counterexample. The same native rules and requests are available to both the query backend and QKF's ordinary unfiltered congruence-closure backend.
- A separate three-physical-phase local source-forcing pilot verifies the provenance of seed facts and forced values beyond the supplied domain. Its source-bound correctness is established within that local profile; the direct-cell route remains the phase default after the A1 comparison.
- A bounded goal-directed planner requests native facts according to the consumer and the currently checked residual obligation and stops when the goal is proved. Every extension of E invalidates stale separators. Candidate exhaustion, insufficient horizon, full nonconsequence, budget stop, empty G and concrete violation remain distinct.
- Chronological E/E+ lemma packages allow a proved source-derived equality to support later consumers. Exact premises, source scope, residual endpoints, acyclic dependencies and `via_lemma` transitivity are checked. `no_lemmas` remains the signed default; reuse is explicit.
- The experimental applicable-summary SDK provides `build → check → apply → explain`, with `assess` for a new consumer and explicit `refine` when the existing summary is insufficient. Positive direct dependency certificates contain checked native and derived foundations. The checker reconstructs the executable target action from the proved request; supplied action tables are not trusted.
- The checked immutable action applies without executing the source. A service assessment and a standalone exported certificate have different delivery contracts. The signed Boolean and local physical-phase profiles remain separate.

Primary guides: [pure rows](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/pure_rows/README_RU.md), [ground queries](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/ground_query/README_RU.md), [native source rules](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/source_query/NATIVE_RULES_RU.md), [source forcing](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/source_forcing/README_RU.md), [source lemmas](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/source_lemmas/README_RU.md), [applicable summaries](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/applicable_summary/README_RU.md), [SDK format/trust map](https://github.com/Len989/QKF-Certifier/blob/eca90f9252da4480d77c1f8cb4b7062470c57b89/research/applicable_summary/FORMAT_TRUST_RU.md).

### 4. Matched lifecycle comparisons and reduced repeated work — PR #46–#49

- Registered comparisons include discovery, built-in checks, SDK adaptation, delivery encoding, fresh receiver checks, assessments, export/explain, applications and build memory. They retain negative, unsupported, empty-domain, exhaustion and exact-repeat controls. Timings from different runners or Python versions are not pooled.
- PR46 isolates native-question selection, query versus ordinary closure, lemma reuse and local forcing. Goal-directed questions reduce native attempts on constructed families, but repeated checkpoints can dominate full cost. Lemma reuse can reduce complete SDK calls for longer batches while its raw backend accounting remains more expensive. These observations do not establish a universal threshold or solver advantage.
- PR47 gives QKF's ordinary route the same SDK and three matched delivery contracts: one summary, a reusable assessment service, and standalone per-goal certificates. `sdk_ordinary`, `once_ordinary` and `each_ordinary` are the frozen next-comparison controls. Ordinary-to-SDK is cheaper on all four core singleton cases on both Python versions; its matched service and standalone controls also win every registered corresponding row. This compares implementations inside QKF.
- PR48 adds an immutable admitted source/IR/profile/G/width context, parsed ground terms and distinct E/E+ prefixes, with native evidence checked on insertion. It separates backend (`ordinary`/`query`) from lemma policy (`no_lemmas`/`reuse`). Complete query/no-lemma cost falls by 9–17% on the registered Python 3.12 cases while peak Python build memory rises by 1.6–5.5%; the simple ordinary SDK control remains cheaper.
- PR49 emits direct dependencies from checked in-memory state. Positive signed paths produce no intermediate native producer packets, pack one final envelope and invoke one final public cold check. Unresolved paths retain the measured scoped-model fallback. All 42 matched PR48/49 pairs retain identical delivery/result bytes, native questions, foundations and checkpoints.
- In matched PR49 query/no-lemma cases, lifecycle medians are 27.96–38.80% lower than PR48 and build-plus-cold-check medians 29.62–39.98% lower. These are per-environment implementation comparisons, not wins over the simple ordinary SDK route. Across four factors, Python peak changes range from −28.83% to +0.45%; scoped fallback costs about 0.4–0.75% more in its two registered environments. Defaults and independent cold-check obligations are preserved.

Complete reports and measurements: [PR46](https://github.com/Len989/QKF-Certifier/blob/435ba478a07f03a6e7d1047b19fd4d39e9fe71b9/research/causal_comparison/REPORT_RU.md), [PR47](https://github.com/Len989/QKF-Certifier/blob/145c64a0985ede5fefa89011a42e5ce454821192/research/sdk_comparison/REPORT_RU.md), [PR48](https://github.com/Len989/QKF-Certifier/blob/10e4fd3c717eeb56d3d887832857c5fd89addf0f/research/prepared_context/REPORT_RU.md), [PR49](https://github.com/Len989/QKF-Certifier/blob/4e2e152a55cd04c4947ffddb0fe31be039f4aaa2/research/direct_emission/REPORT_RU.md). ### 5. Lean soundness for ground DAGs and chronological composition — PR #50–#51

`formal/ground` proves soundness of the decoded positive typed ground calculus: topological term decoding, chronological axiom/congruence events, reflexive/symmetric/transitive paths and declared depth/activity checks. `check_sound` gives equality in every model of the supplied E; `accepted_goal_values` gives equality of actual values in a common sort. The adapter retains all equations/events and explicitly indexes excluded negative goals. Its integration fixtures include 9 real exported DAGs with 32 positive goals and 28 rejected DAGs.

`formal/composition` imports the unchanged ground package and proves chronological lemma import, exact premise/residual binding, `via_lemma` transitivity, preservation of the original model class, and equality of accepted consumer values. Its fixtures include 12 positive packets with 56 consumers, a two-lemma chain and four original PR49 packets spanning ordinary/query × no_lemmas/reuse; 17 negative packets are rejected by the Lean kernel.

Both packages pin Lean 4.33.0 / Std. The ground package has 13 audited general theorems and 50 audited declarations overall; composition adds 12 general theorems and audits all 41 theorem/example entries. Accepted dependencies use only standard `propext` and `Quot.sound`. Proof-hole and extra-axiom integrity controls are enforced; acceptance does not rely on native evaluation shortcuts.

This completes F1a/F1b **for the decoded typed calculus and composition under native assumptions**. It does not formally verify the Python JSON parser, name mapping, source frontend, native source rules, lower models, minimal horizon, proof-search completeness, interface-to-runtime correspondence or a complete transformer.

At the recorded final PR51 head `3ed16a0b01096479dce8ea367144de8ba3478c39`, all 32 workflow runs passed; the current-tree matrix ran 1,158 registered tests separately in normal and optimized modes on Python 3.10 and 3.12. The formal artifact independently matches the 59 formal-package files and all 2,405 blobs/modes of that head. These are recorded PR51 results, not a claim that a subsequently assembled release artifact was itself tested.

Reports are on separate results-only commits and must be included explicitly if the release source archive is expected to contain them: [PR50 report](https://github.com/Len989/QKF-Certifier/blob/e210e63dbf19f045f3ad84b528a22810c1fb4d2e/formal/ground/REPORT_RU.md), [PR50 validation](https://github.com/Len989/QKF-Certifier/blob/e210e63dbf19f045f3ad84b528a22810c1fb4d2e/formal/ground/VALIDATION.json), [PR51 report](https://github.com/Len989/QKF-Certifier/blob/ab43bbe11ed99ff5e21808a34351c37915a1ec2f/formal/composition/REPORT_RU.md), [PR51 validation](https://github.com/Len989/QKF-Certifier/blob/ab43bbe11ed99ff5e21808a34351c37915a1ec2f/formal/composition/VALIDATION.json), [theorem and trust map](https://github.com/Len989/QKF-Certifier/blob/3ed16a0b01096479dce8ea367144de8ba3478c39/formal/composition/README_RU.md).

Source-model equivalence, a source-free mathematical equality, a proof for an independent consumer, a finite counterexample, a bounded nonvisibility result and a chosen completion are distinct evidence types. Their schemas and claims must not be collapsed in the release description. Repeated executions on two Python versions or under `-O` do not multiply program coverage. Historical results remain attached to their exact engines and inputs.
